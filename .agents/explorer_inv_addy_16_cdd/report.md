## Purpose — required, verbatim
> "Establishes a project's quality bar as a written contract and stops agents quietly lowering it. Interviews the user on which dimensions matter, supplies sane default thresholds when they have no number in mind, records everything in CONSTRAINTS.md, and watches the diff for a weakened bar — new @ts-ignore or eslint-disable suppressions, skipped or deleted tests, assertions stripped out, unimplemented stubs, thresholds edited down. Use when no quality bar is written down, when the user says \"set up constraints\" or \"define our standards\", when an agent keeps silencing checks or skipping tests to get to green, when you need a coverage or performance threshold and don't know what number to pick, or when an agent writes more code than anyone will read." — skills/constraint-driven-development/SKILL.md:3

## Design intent — required
Prevents autonomous and human-directed coding agents from quietly degrading codebase quality when striving to reach green builds ("the cheapest road to green"). While other skills offer advisory prose on quality, reviewing, or testing, this skill creates an authoritative, persistent, mechanically verifiable repository contract (`CONSTRAINTS.md`) with explicit numeric thresholds, cost-tiered execution points, and anti-evasion diff guards. It provides a structured 4-question intake interview with sensible defaults so teams can establish an actionable baseline immediately, employs ratchets to hold existing metrics without blocking progress on legacy debt, and enforces a zero-dependency baseline "Floor" that catches suppression comments, stripped assertions, and deleted tests in git diffs.

## 3. Edge Cases

| # | Feature | Input | Observed Behavior |
|---|---------|-------|-------------------|
| 1 | Floor Guard | Missing live URL for CLI / library | Tool drops accessibility (axe) and performance (Lighthouse) checks explicitly instead of inventing mock checks (`SKILL.md:165`). |
| 2 | Floor Guard (`floor-guard.mjs`) | Non-git repo or missing git merge base | Script logs error to stderr and terminates immediately with exit code `2` (`floor-guard.md:35`). |
| 3 | Floor Guard (`floor-guard.mjs`) | Clean diff against merge base | Prints `floor-guard: clean` to stdout and terminates with exit code `0` (`floor-guard.md:88`). |
| 4 | Floor Guard (`floor-guard.mjs`) | Untracked file containing suppression (`@ts-ignore`) | Due to `execFileSync` throwing on exit code 1 from `git diff --no-index`, untracked files return empty string and violations are dropped (`floor-guard.md:28-42` defect). |
| 5 | Floor Guard (`floor-guard.mjs`) | Entire test file deleted in diff | Git diff header `+++ /dev/null` slices to `'v/null'`, failing test file regex check and allowing test file deletion without flagging (`floor-guard.md:48, 72` defect). |
| 6 | Floor Guard (`floor-guard.mjs`) | Lowering coverage threshold from 80% to 70% in `CONSTRAINTS.md` | Detected and flagged as `[threshold-lowered]` with exit code `1` (`floor-guard.md:83-85`). |
| 7 | Floor Guard (`floor-guard.mjs`) | Deleting a constraint row from `CONSTRAINTS.md` without replacement | `addedConstraints.find(...)` returns undefined; deletion is not flagged (`floor-guard.md:81-85` defect). |
| 8 | Floor Guard (`floor-guard.mjs`) | Exception line with violation text exceeding 120 chars | Script redacts line output to exactly 120 characters via `text.trim().slice(0, 120)` to prevent secrets/data leaks in error messages (`floor-guard.md:54`). |
| 9 | Intake Dialogue | User coverage is 62% and user requests enforcing 85% immediately | Skill pushes back against broken build, proposes ratcheting today's number (62%), and enforces ratchet instead of unachievable jump (`evals/cases/constraint-driven-development.json:58-65`). |
| 10 | Intake Dialogue | User has no number in mind for coverage or limits | Offers sane defaults: changed lines ≥ 80%, project coverage hold, mutation score ≥ 60%, exception lifetime 90 days (`SKILL.md:238-249`). |
