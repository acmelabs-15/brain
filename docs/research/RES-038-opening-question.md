# RES-038: A question before the first word

## Question
Can a turn started before the first word show an ask-user-question prompt on Claude Code, from a plugin with no user setup?

## Findings
- Test method: every "local test" below ran on Claude Code 2.1.318 in a real interactive session, in a throwaway folder, with a throwaway plugin from `--plugin-dir` unless it says otherwise, `--setting-sources project` and the haiku model, one run per case unless it gives a count. A Bun PTY driver typed the keys and a small terminal emulator read the screen; the oracle was the screen, plus a hook log of `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop` and `Notification`. No session log was read. The emulator mis-drew some rows after a scroll, so a screen claim here rests on rows that drew clean, and my first resume and fork checks failed on that fault, not on Claude Code. Source: local test, checked 2026-11-05.
- A plugin `SessionStart` hook with `asyncRewake` and exit 2 opened the real `AskUserQuestion` dialog on `startup` with no user input: the turn called the Skill tool, then `AskUserQuestion`, and the dialog stood on screen about 4 to 5 seconds after launch. With 60 seconds of no input the screen stayed the same and the agent took no step; after Down and Enter, `PostToolUse` carried `"A bug"` and the agent replied `ANSWER-SEEN: A bug`. Source: local test, checked 2026-11-05.
- A mod's `$.command.run` of a skill, on a timer from `session.start`, opened the same dialog on `startup` with no user input, about 4 seconds after launch, with the same proof: 60 seconds with the screen unchanged and no agent step, then the answer reached the agent. Source: local test, checked 2026-11-05.
- `AskUserQuestion` opened with no permission prompt in the started turn, and so did the plugin skill's Skill call, in auto, Manual (`--permission-mode default`) and plan mode, for both mechanisms. The tools table marks the Skill tool as needing permission, so this is tested behavior for a plugin skill that declares no tools. Source: local test, https://code.claude.com/docs/en/tools-reference, checked 2026-11-05.
- Before the dialog, the user sees the normal welcome screen and an empty prompt box for about 1 second. With `asyncRewake` a row "Stop hook feedback" then appears with a spinner, and the row stays in the transcript above the dialog; a skill call adds "Skill(oqa:opening)" and "Successfully loaded skill". No row says "error" on screen. With the mod, a user line `/oqb:opening` appears instead, the way a typed command does, and no hook row. The prompt box stays live until the dialog opens. Source: local test, checked 2026-11-05.
- The agent receives the `asyncRewake` text as a user-side `<task-notification>` with the summary "Stop hook feedback" and a system reminder that begins `Stop hook blocking error from command "SessionStart:startup":`. It also fires `UserPromptSubmit` with that text, and the mod's run fires `UserPromptSubmit` with `/oqb:opening`. Source: local test, checked 2026-11-05.
- With a draft in the prompt box, the host holds the dialog back: `AskUserQuestion` was called, but the screen showed "Waiting for permission…", the keys stayed in the box, and no key reached the dialog, on both mechanisms. Enter then sent the draft as a queued prompt and the dialog opened after it. Source: local test, checked 2026-11-05.
- A draft typed before the dialog and left unsent survives it: the dialog opened over the box, the answer went through, and "fix bug" was still in the prompt box afterwards, on both mechanisms. Source: local test, checked 2026-11-05.
- At the open dialog, letters do nothing and show nowhere, and Enter then picks the highlighted first row: "hello there" plus Enter answered "Active item" and the text was lost, on both mechanisms. A digit picks its row at once with no Enter. Source: local test, checked 2026-11-05.
- Free text goes through the fourth row, "Type something": arrow down, type, Enter, and `PostToolUse` carried "my own words" to the agent. The fifth row, "Chat about this", declines the question and the agent then asks what to clarify, leaving the prompt box free. Both held on both mechanisms. Source: local test, checked 2026-11-05.
- Esc at the dialog prints "User declined to answer questions", ends the turn with no `Stop` hook and no further agent text, and leaves an empty prompt box. One Ctrl-C leaves the dialog open. Both held on both mechanisms. Source: local test, checked 2026-11-05.
- Startup rate: with no input, the dialog opened and the answer reached the agent in 5 of 5 `asyncRewake` runs and 5 of 5 mod runs on haiku, and in 2 of 2 of each on the session default, Opus 5.5. Alone or with one other session, the dialog took about 3.5 to 5 seconds from launch; with ten sessions at once, 8 to 10 seconds for `asyncRewake` and 6 to 7 seconds for the mod. Source: local test, checked 2026-11-05.
- A first prompt sent before the wake, about 0.5 seconds after launch, ran as its own turn and got its reply, and the opening question then opened anyway, on both mechanisms. The user is asked what to work on just after asking for something. Source: local test, checked 2026-11-05.
- A first prompt sent during the started turn splits the mechanisms. With `asyncRewake` and a skill, the prompt reached the agent inside the Skill tool result: in 6 haiku runs, 3 showed the dialog and dropped the prompt as "tool output, not from you", 1 dropped the prompt and asked in plain text with no dialog, and 2 replied to the prompt with no question at all. With the mod, in 6 of 6 haiku runs the dialog opened, and after the answer the agent replied to the prompt. Source: local test, checked 2026-11-05.
- `SessionStart` with `asyncRewake` fired on all five sources, and the wake started a turn on each. The dialog followed only where the agent chose it: `startup`, `clear` (1 run) and `/branch` (1 run) opened it. On `/compact` (1 run), `--resume` (3 runs), `--continue` (1 run), `--resume --fork-session` (3 runs) and in-session `/resume` (1 run), the agent called no `AskUserQuestion` in any of the 9 runs: it printed text saying the question was already answered, often with a plain-text question about the bug. Those conversations held the earlier answer. In one run the text said "The same stop hook keeps firing". Source: local test, checked 2026-11-05.
- `/branch` is `SessionStart` source `fork`, and it fired in the same process. Source: https://code.claude.com/docs/en/hooks#sessionstart, local test, checked 2026-11-05.
- A mod's `session.start` fires once per process, so `$.command.run` from it opened the dialog on `startup` and on a new process with `--resume` or `--resume --fork-session`, even when the conversation held an earlier answer, and the answer reached the agent. It did not fire on `/clear`, `/compact`, `/branch` or in-session `/resume`: no dialog, no turn. Source: local test, https://code.claude.com/docs/en/plugins/mods/reference#session, checked 2026-11-05.
- A mod's `classic.SessionStart` hook closes that gap. It fires "whether or not any settings hook is configured" and carries `source`, and a `$.command.run` on a timer from it opened the dialog on `startup`, `clear`, `compact`, `resume`, `fork`, `/branch` and in-session `/resume`, at least one run each, with the answer reaching the agent. In one `fork` run the agent called `AskUserQuestion` a second time after the answer. This variant was not in the row's two mechanisms; I added it because `session.start` left those sources open. Source: local test, the `ClassicEventName` type in the `claude-code.d.ts` that Claude Code 2.1.318 writes, checked 2026-11-05.
- The prompt loss comes from the skill round trip, not from `asyncRewake` itself: with the question written into the hook text and no Skill call, 5 of 5 haiku runs opened the dialog and then replied to the mid-turn prompt, as the mod does. On Opus 5.5 with a skill, 3 of 3 `asyncRewake` runs replied to the prompt and dropped the question, while 3 of 3 mod runs opened the dialog and then replied to the prompt. Source: local test, checked 2026-11-05.
- The hold-back ends about 1.4 seconds after the last key, on both mechanisms, and the dialog then takes the keys. A user who typed "fix", paused, and went on with " the login bug" and Enter answered "Active item" by accident: the later letters were lost, and "fix" stayed in the prompt box. Source: local test, checked 2026-11-05.
- `--continue` is source `resume` and behaved as `--resume`: the `asyncRewake` wake started a turn with no dialog, and the mod opened the dialog. Source: local test, checked 2026-11-05.
- The dialog waits: with no input for 5 minutes, the screen stayed the same and the only hook event was one `Notification` of type `permission_prompt`, about 6 seconds after the dialog opened, on both mechanisms. The answer then reached the agent. The docs say a question stays open until answered unless `askUserQuestionTimeout` is set; these runs did not load user settings, so that setting was not in play. Source: local test, https://code.claude.com/docs/en/tools-reference#askuserquestion-tool-behavior, checked 2026-11-05.
- Neither mechanism needed a user step beyond the folder trust dialog every new folder shows, whose default row is "No, exit". Nothing of the mod ran while that dialog was open: 8 seconds open gave no hook event and no `session.start`, and the question opened 4.8 seconds after "Yes". With `asyncRewake`, "No, exit" ran no hook, and "Yes" brought the question within 5 seconds. Source: local test, checked 2026-11-05.
- Marketplace install behaved the same as `--plugin-dir`, for both mechanisms on `startup`: dialog, 20-second hold, answer reached the agent, and no new dialog. I tested two sources: a local directory marketplace, which loads the plugin in place, and a plugin `url` source on a local `file://` git repository, which ran from `cache/oqgit/<plugin>/0.1.0`, the layout of a real install, as the running path proved. Only `startup` was run this way. Source: local test, https://code.claude.com/docs/en/plugins/marketplace-reference#plugin-sources, checked 2026-11-05.
- That install stayed out of the user's files: `CLAUDE_CODE_PLUGIN_CACHE_DIR` and `CLAUDE_CONFIG_DIR` pointed the install at the throwaway folder, `--scope project` put `enabledPlugins` in the folder's own `.claude/settings.json`, and the hashes of `~/.claude/settings.json`, `plugins/known_marketplaces.json` and `plugins/installed_plugins.json` did not change. The session itself used the real config folder for sign-in, because a `CLAUDE_CONFIG_DIR` session had no login. Source: local test, https://code.claude.com/docs/en/env-vars, checked 2026-11-05.
- `$.command.run` needs the timer: the type file says it rejects "inside a hook the turn or the session's start waits on". `$.clock.after(0, ...)` from `session.start` was enough in 1 run, and the dialog came in 4.3 seconds. Source: the `command.run` doc in the `claude-code.d.ts` that Claude Code 2.1.318 writes, local test, checked 2026-11-05.
- A `-p` run with the instant `asyncRewake` hook was not disturbed: one turn, the reply to its prompt, no second turn, exit 0 (1 run). The docs offer `AskUserQuestion` in a `-p` run only when it has a permission host. Source: local test, https://code.claude.com/docs/en/hooks#tools-that-require-user-interaction, checked 2026-11-05.
- Neither mechanism runs under `--safe-mode` or `disableAllHooks`, and a mod also stops under `--bare` or the organization's `allowManagedModsOnly`, by the docs. None of these was run. Source: https://code.claude.com/docs/en/plugins/mods/overview#turn-mods-on-or-off, https://code.claude.com/docs/en/hooks#disable-or-remove-hooks, checked 2026-11-05.
- A third route showed up outside the row's two mechanisms: a mod's `$.ui.ask` opens "the engine's own AskUserQuestion dialog" with no model turn. From `session.start` it stood on screen 0.9 seconds after launch, with no `UserPromptSubmit` before it, and it fires `PreToolUse` and `PostToolUse` for `AskUserQuestion`. The answer returned to the mod, and `$.prompt.submit` with `asUser: true` handed it to the agent under a line "Prompt from the oqd plugin". With an early prompt, the prompt got its reply and the answer followed. Three runs, `startup` only. Source: the `ui.ask` doc in the `claude-code.d.ts` that Claude Code 2.1.318 writes, local test, checked 2026-11-05.
- This record answers two UNVERIFIED lines of RES-035 and widens one table row: an `asyncRewake` hook wakes on `resume` and `fork`; the mechanisms behave the same from a marketplace install, on `startup`; and `$.command.run` from `session.start` also covers `resume` and `fork` on a new process. Source: docs/research/RES-035-auto-start-mechanisms.md:108, docs/research/RES-035-auto-start-mechanisms.md:113, docs/research/RES-035-auto-start-mechanisms.md:137, local test, checked 2026-11-05.

## Follow-ups
- Should the opening question use `$.ui.ask`, with no model turn, in place of a started turn? It needs its own row: every source, a draft in the box, a mid-turn prompt, and where the mod guard loads.
- Which session sources should ask? The forced mod asks on `compact`, so the question can open in the middle of a task, while `asyncRewake` lets the agent skip it and print text.
- Should the question text sit in the hook or in a skill, given that a skill round trip lost the user's first prompt in the `asyncRewake` runs?
- Which option goes first, given that a stray Enter picks the highlighted first row?
- UNVERIFIED: a plugin installed at user scope from a real GitHub marketplace behaves as these project-scope installs did, since a user-scope install writes to user settings.
- UNVERIFIED: either mechanism behaves the same with user settings loaded, other plugins and MCP servers running, or `askUserQuestionTimeout` set. Every test used `--setting-sources project`.
- UNVERIFIED: `$.command.run` and `$.ui.ask` work where the mod guard loads, on a Team or Enterprise `/login` or a managed machine. The mods admin page names neither.
- UNVERIFIED: either mechanism opens the dialog in the VS Code extension or the Desktop app. Only the terminal was run.
- UNVERIFIED: an automatic compaction acts as `/compact` did. Only `/compact` was run.
- UNVERIFIED: the agent also skips the question on `resume` and `fork` when the conversation holds no earlier answer, or with other hook wording. All 9 such runs used one wording and held an answer.
- UNVERIFIED: the rates hold on Sonnet. Only haiku and Opus 5.5 were run, and `clear`, `compact` and `/branch` had one run each.
