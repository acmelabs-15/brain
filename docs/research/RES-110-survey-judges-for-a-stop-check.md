# RES-110: Survey: what can judge the moment to stop an agent

## Question
Survey, area 2 of 3: which options can judge the moment where an agent must stop and talk with the user, and what is known of each, for the eight survey questions?

## Answer
This is a map of 15 options in six kinds. It is not a recommendation.

**No source measures any judge on the three moments.** The nearest measurements are of three other judgments: "does this action go past what the user authorized", "does this action fit the user's goal" and "must the agent ask the user now". All sources agree on one more point: measure the judge on your own labeled cases before you trust it.

How the sources were read: pages came as raw page text or raw markdown. A quote in Findings is from that text. "Vendor" in the table means the maker measured it.

### What a rule with no model could decide

The sources state what a rule can read: the tool name, the tool input with its file path, and the transcript file. They also state that a call to `AskUserQuestion` and a call to `Agent` are tool names that a hook sees. The three points below are this record's reading of those facts. No source tests them.

- **Moment 2** (a delegated agent returns, and the agent records the result as final) is mostly a fact of order: a delegated agent returned, then a write to a record came, and no question to the user came between. A rule can decide that part.
- **Moment 1** (the user pushes back, and the agent writes a note or a rule) has one part a rule can see: a write to a notes or rules file with no question first. "The user pushed back" is a fact of meaning. A rule can only use a coarse stand-in for it.
- **Moment 3** (the user's direction conflicts with a skill instruction) is a fact of meaning on both sides. The sources give a rule nothing to read it from.

One limit applies to all three: the transcript file can lag the current turn.

### Where the sources agree

- Rules come first and a model judges only the rest. Anthropic's auto mode, OpenAI's safeguard guidance and TypeSafe's build guide all say this.
- A judge needs a threshold or a prompt that is tuned on your own labeled cases. OpenAI, Google, NVIDIA, the Vercel AI SDK and the independent Jev paper all say this.
- A model judge gives no guarantee. Anthropic, OpenAI and Meta each say so about their own judge.
- Text that the judge reads can move the judge. TypeSafe, Google and Meta each warn of this.
- The hard part is the link between an action and what the user said. The auto mode misses, OpenAI's statement on user intent and Jev's grounding scores all point to it.

### Where the sources disagree

- **What the judge reads.** Anthropic removes assistant text and tool results and reports worse results with them. OpenAI's reviewer reads assistant updates and tool outputs as untrusted evidence. Meta's auditor reads the agent's reasoning and leaves out tool outputs.
- **Small model or large model.** Makers of decision models say a small fast model matches mid-size models on typed questions. Meta says small judges block too much. OpenAI says larger models read user intent better. Anthropic and OpenAI both use a mid-size or large model for their own judge.
- **Can the model check itself.** Research on self-correction says no, when no outside signal exists. Two studies say a separate role helps, even with the same model: a separate "must we ask" checker, and the same claim sent back from an outside role.
- **Calibration.** Vendors of decision models say "calibrated". The independent paper confirms it for choice questions and not for yes/no questions at a fixed 0.5. OpenAI does not claim it. The Vercel AI SDK promises none across providers.
- **Open or closed on failure.** Claude Code hooks let the call go ahead by default. Auto mode, NeMo and OpenAI's guidance block. Codex says a timeout is not proof of danger.
- **Trained classifier or written policy.** OpenAI says a classifier trained on many labels beats a model that reads a policy. No labeled cases of the three moments exist, so only the written-policy kinds can start today.
- **Speed of Jev.** The vendor says about 100 ms, an independent paper measures 0.36 s, and a competitor measures 524 ms.

Evidence against popular claims: "judges agree with humans 85% of the time" shrinks to a kappa near 0.48 after correction for chance. "A decision model cannot hallucinate" is true of its output type only; its grounding accuracy ranges from 59.8% to 90.6%.

### Worth a deep run

1. **A separate "must we ask" checker.** One peer-reviewed study gives a yes or no at each turn and forces a question to the user. It is the nearest published design to this check, and the same model served both roles. A deep run must test it on real sessions with the three moments.
2. **What the judge reads.** Anthropic, OpenAI and Meta chose three different inputs, and each reports numbers. Anthropic's main miss, approval-like text that does not cover the action, is the same shape as "did the user talk about this". The input choice may matter more than the model choice.
3. **Decision models as the judge.** They are cheap and fast, and they return a probability that a threshold can use. No source tests them on a conversation. The deep run needs labeled cases and a comparison of B, C, D and E with a small general model, with privacy as one axis.
4. **The rule-first split.** Each moment has a part that code can decide and a part that needs meaning. A deep run can find how much of each moment the rule part already catches, and what is left for a model.
5. **The auto mode classifier and Codex Auto-review as prior art.** Both judge user authorization from a transcript and a tool call, and both publish their prompt design and error rates. Their open policy text is direct input for area 3 of this survey.

- TypeSafe's page of workflow tests and the collapsed answers of its FAQ.
- Any measurement of a decision model on conversation input.
- Google's data use terms for the Decisions API.
- What Claude Code does when a prompt hook or agent hook times out.
- A direct test of a yes/no question against a score for this kind of judgment; area 3 covers it.
- UNVERIFIED: an OpenAI page appears to say that an action does not run after a review timeout. The text was cut off in the result.

## Findings
- Vendor claim: Jev is the first "System One" model of TypeSafe; it reads a state and typed questions and returns typed answers with probabilities, and it writes no text. Source: https://docs.typesafe.ai/concepts/system-one, checked 2026-11-21.
- Jev has four question types: Choice (one option, a probability for each option, a confidence), Score (a place on 2 to 10 ordered levels), Noul (the probability of yes, with no separate confidence) and Box (a region of an image, Jev 1.14 only). Source: https://docs.typesafe.ai/models, checked 2026-11-21.
- Jev costs $0.042 for each million input tokens and output tokens are free; the default context is 64k tokens for each request and 32k for each question; the newest release is jev-1.14.0 from 2026-10-14. Source: https://docs.typesafe.ai/models, checked 2026-11-21.
- Vendor claim: most Jev calls complete in about 100 ms, and the launch post gives an end-to-end range of 70 ms to 500 ms. Source: https://typesafe.ai/blog/introducing-system-one-models-and-jev, checked 2026-11-21.
- Vendor claim: the home page figures "193.6x faster, 444.6x cheaper" come from workflow tests that TypeSafe staff wrote, with the average of two large models as the reference answer; the vendor calls the figures "the higher end of real world gains". Source: https://typesafe.ai/blog/introducing-system-one-models-and-jev, checked 2026-11-21.
- Independent measurement: an arXiv paper tested jev-1.13.0 on 37 datasets with 346,009 requests for US$9.15, at a mean latency of 0.36 s for each request at 32 parallel requests. Source: https://arxiv.org/abs/2609.37647, checked 2026-11-21.
- Independent measurement: Jev Choice probabilities are well calibrated (pooled expected calibration error 0.028 on 22 datasets), single Noul probabilities are a little under-confident (0.052), and many Noul questions in one request over-predict yes (0.168). Source: https://arxiv.org/abs/2609.37647, checked 2026-11-21.
- Independent measurement: a Noul cut at 0.5 gives poor decisions where ranking is good; on a prompt-injection set Jev has perfect precision and 50% recall at an AUROC of 0.982, and a tuned threshold raises micro-F1 on UNFAIR-ToS from 0.50 to 0.75. Source: https://arxiv.org/abs/2609.37647, checked 2026-11-21.
- Independent measurement: Jev is weakest on judgments of generated text against a rubric; on HelpSteer2 its scores for helpfulness and correctness correlate 0.399 and 0.369 with human ratings, and a 27B open model does the same or a little better on rubric scores. Source: https://arxiv.org/abs/2609.37647, checked 2026-11-21.
- Independent measurement: on the grounding check LLM-AggreFact, which asks if a text supports a claim, Jev's mean balanced accuracy is 78.6%, with a range from 59.8% to 90.6% by source. Source: https://arxiv.org/abs/2609.37647, checked 2026-11-21.
- Vendor statement: Jev reads instructions literally, loses accuracy on indirection and on a large state full of unrelated detail, can be moved by adversarial text in the state, and leans to the first option of a Choice. Source: https://docs.typesafe.ai/model-jaggedness, checked 2026-11-21.
- Vendor advice: keep rules that code can decide in code, ask narrow separate questions, send only the context each question needs, and send uncertain answers to a person or a larger model; the start values for a Noul are 0.7 for yes and 0.3 for no. Source: https://docs.typesafe.ai/concepts/how-to-build-with-system-one, checked 2026-11-21.
- Vendor statement: Jev is not trained on customer requests or responses, the vendor publishes no fixed retention period, processing is in the United States, and zero data retention is "free for every organization". Source: https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained, checked 2026-11-21.
- TypeSafe's enterprise page says zero data retention is "available for enterprise customers", which differs from the help article. Source: https://typesafe.ai/enterprise, checked 2026-11-21.
- A Jev request over a rate limit returns 429, and the vendor SDKs retry with a longer wait each time; the sources give no advice to fail open or closed. Source: https://docs.typesafe.ai/models, checked 2026-11-21.
- TanStack AI `decide()` sends one state and a map of `choice`, `score` and `boolean` questions to a decision model and returns typed fields with probabilities; it has no stream. Source: https://tanstack.com/ai/latest/docs/evaluate/evaluate, checked 2026-11-21.
