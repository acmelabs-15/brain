# RES-074: What UI a mod can draw

## Question
What UI can a Claude Code mod draw in a session: its render sites, elements, focus, scrolling, key input and registered commands, and their limits in the terminal, VS Code and Desktop? Can it lay out board columns side by side and draw a dependency graph between cards?

## Answer
Sufficient answer: for each UI call and render site that could carry a full view, give its signature, what it draws, and where it works (terminal, VS Code extension, Desktop). Then answer: can a view show several columns side by side and scroll each; can the user move between cards with keys and open one; can a view draw lines or arrows between cards, or must a graph be text, an image or a web page; can the view re-render when files change; how does the user open a view; size, rate or element limits; and the minimum Claude Code version for each. Name contrary evidence and what stays unknown. Scope added on 2026-11-20 from Peter's answer, who wants the views in a resizable panel beside the working session: (1) can the user or the mod resize a pane, and how (keys, mouse, call options); (2) does a pane stay visible and keep updating while a turn runs and the agent writes files; (3) can the prompt box stay usable while the pane is open. This serves IDEA-015#08, #12, #13 and #14.

A full view lives in a pane. A mod opens it with `$.ui.open` from a slash command it registers, and draws it in a `ui.render` hook from flex boxes, text, Markdown, links and controls. The terminal test drew a four-column board, a detail view and a text graph, and re-drew them when files changed.

### The calls and sites that can carry a view

| Call or site | Signature | What it draws or does | Terminal | Desktop | VS Code | Version |
|---|---|---|---|---|---|---|
| `Pane` site | `ui.render` with `{ component: 'Pane' }`, `e.requestId` is the pane id | The view itself: a framed region, docked beside the transcript or inline above the prompt | Yes | Yes | Yes | mods; VS Code extension 2.1.299 |
| `AbovePrompt` site | `ui.render` with `{ component: 'AbovePrompt' }` | One row per mod in the band above the prompt, at most half the terminal's rows, collapsible by the user | Yes | Yes | No | mods; one row per mod 2.1.323 |
| `$.ui.open` | `(pane: { id, title?, focus?, closeOnEscape?, holdToasts?, backgroundColor?, rows?, columns?, placement? }) => Promise<{ isPlaced: true } \| { isPlaced: false, reason }>` | Opens a pane; `ui.render` then draws it | Yes | Yes | Yes, ignores `rows` and `columns` | mods |
| `$.ui.close`, `$.ui.panes` | `({ id }) => Promise<void>`; `() => Promise<UiPane[]>` | Close a pane; list the mod's panes with `isShown`, `isFocused`, `isPlaced` | Yes | Yes | Yes | mods |
| `$.ui.focus` | `({ requestId, key }) => Promise<{ deny? }>` | Moves the focus ring onto a keyed `Button`, `Input` or `Select` | Yes (tested) | By type file | By type file | mods |
| `$.ui.scroll` | `({ to, in?, block? }) => Promise<{ deny? }>` | Brings a keyed element or the start or end of a pane into view | Yes | By type file | By type file | mods |
| `$.ui.invalidate` | `(event) => void` | Runs `ui.render` again; at most 10 redraws a second, 30 in the terminal | Yes (tested) | Yes | Yes | mods |
| `$.ui.blit` | `({ requestId, key, cells \| source, columns, rows }) => Promise<{ deny? }>` | Repaints a `Raster` or swaps an `Image` without a redraw | Yes | No `Raster`, `Image` | No | mods |
| `$.ui.place` | `({ id }) => Promise<{ isPlaced, requestId? }>` | One row at the end of the transcript; scrolls away, not a view | Yes | No | No | 2.1.314 |
| `$.ui.view` | `({ agentId? }) => Promise<{ deny? }>` | Shows a subagent's transcript; cannot show a mod's view | Yes | Yes | Yes | 2.1.300 |
| `$.command.register` | `({ name, description, argumentHint?, immediate? }) => Promise<{ command }>` | Adds `/<name>`; a `command.run` hook answers it | Yes (tested) | Yes | Yes | mods |
| `Box`, `Text`, `Button`, `Markdown`, `Link`, `Select`, `Input`, `Code` | elements from `$.ui.resolve(e)` | Flex layout, styled text, controls, formatted Markdown, links, dropdowns | Yes | Yes | Yes, with ignored props | mods |
| `Svg` | `{ source ≤ 131,072 chars, alt, width, height }` | An SVG picture | No | Yes | Yes | not stated |
| `Raster` | `{ key, columns ≤ 512, rows ≤ 256, cells }` | Colored character cells | Yes (tested) | No | No | not stated |
| `Image` | `{ key, source ≤ 2 MiB, columns, rows ≤ 255, alt }` | A picture in kitty, Ghostty or iTerm2; `alt` text elsewhere | Yes | No | No | iTerm2 2.1.305 |
| `Client` | `{ key, module, props, width, height, flexGrow }` | A region a second module draws with terminal elements, with pointer and key input; not a web page | Yes | Yes | No | not stated |

"mods" means the first version with mods: v2.1.287 in the terminal and v2.1.286 in Desktop. The docs give no later version for these calls and elements.

### Answers for the map rows
- **Columns side by side (row 08)**: yes. A `Box` with `flexDirection: 'row'` drew four bordered columns side by side, inline and docked. An inline pane is as wide as the terminal but a third as high, unless `rows` asks for more. A docked pane had 77 of 200 columns and can grow to at most 45%.
- **Scroll each column (row 08)**: not built in. No `Box` scrolls by itself, and the pane scrolls the whole tree as one. A mod can show a window of each column and move it itself: a `ui.scroll` hook that read `pointer.column` and refused the pane's move scrolled one column at a time in the test. Keys can move such a window through hotkeys.
- **Move between cards and open one (row 08)**: yes. Tab moves the focus in drawing order, and so do Up and Down while the board fits the pane. Enter presses the focused card. Left and Right did nothing in a pane, so two-way moves need letter hotkeys and `$.ui.focus`, which worked. VS Code has no hotkeys: the user clicks or tabs there.
- **Lines and arrows (row 08)**: no element draws a line between two elements. In the terminal a graph is text with box-drawing characters, absolute `Box` positions or `Raster` cells, all of which drew in the test, or an `Image` picture in three terminals. Desktop and VS Code can draw an `Svg`. No element on any surface is a web page.
- **Re-render on file change (row 13)**: yes. A mod's `classic.SessionStart` returned `watchPaths`, `classic.FileChanged` fired for the files and for new files in nested folders, and `$.ui.invalidate` re-drew the pane. It worked while the agent's own `Bash` wrote records during a turn. Where the built-in guard loads, a user's mod's `classic.*` hooks do not run, so the fallback is a poll with `$.clock.every` and `$.fs.stat` or `$.fs.list`.
- **How the user opens a view (row 12)**: a slash command from `$.command.register`; with `immediate: true` it opened the pane while a turn ran. The user can also bind a key in their own `keybindings.json` to `command:<name>`; a `ctrl+x ctrl+o` chord opened the pane. The mods API cannot bind a key itself. A pane a mod opens without a user action shows only from 144 terminal columns.
- **Other surfaces (row 14)**: Desktop draws the pane and most elements, with `Svg` and `Client` but no `Raster` or `Image`. VS Code draws the pane but no band, `Client`, `Raster` or `Image`; it ignores absolute positions and hotkeys. Nothing draws in `claude -p` or the Agent SDK.
- **Limits**: 20,000 elements and text children per tree, 32 levels of nesting, 100,000 characters of text drawn, 262,144 `Raster` cells and 2 MiB of `Image` bytes per tree. A tree over a limit is not drawn. A `ui.render` hook has 10 seconds of its own time.

### Answers for the panel beside the session (added scope)
- **A panel beside the session needs fullscreen rendering.** A pane docks beside the transcript only in fullscreen and from 110 columns. In the classic renderer, or a narrower terminal, it sits above the prompt at full width.
- **The user can resize a pane.** Ctrl+X then Left or Up gives it more room, and Ctrl+X then Right or Down gives room back: one row for an inline pane, four columns for a docked one in the test. Dragging the pane's edge with the mouse also worked in fullscreen. A docked pane stops at 45% of the terminal's width.
- **The mod can resize a pane until the user does.** A second `$.ui.open` with the same `id` and new `columns` or `rows` resized the open pane: a docked one from 40 to 60 columns, an inline one from 8 to 20 rows. Once the user has set a size, in this session or an earlier one, the mod's request changes nothing. `$.ui.place` takes only an `id` and has no size.
- **The size the user sets is kept.** Claude Code writes it to the config folder's `.claude.json` as `pluginPanes.dockColumns` or `pluginPanes.inlineRows`, one value for all mods' panes. In this machine's own config `dockColumns` is 78, so every docked pane here opened 77 body columns wide.
- **The pane stays and updates during a turn.** A docked pane stayed beside the transcript for the whole turn, and each file the agent's `Bash` call wrote re-drew it while the spinner ran. An inline pane did the same.
- **The prompt box stays usable.** With `closeOnEscape` left out, Esc handed the keys to the prompt and the pane stayed open. The user then sent a prompt and typed a draft during the turn. Ctrl+X Tab moved the keys into the pane, a hotkey worked there, and Esc moved them back with the draft kept. A pane opened with `closeOnEscape` also closes on Esc at an idle, empty prompt, so a side panel should leave it out.

### Contrary evidence
- `$.ui.view` is not a view call: it switches the transcript to a subagent's.
- `Client` is not a web page. It draws with the terminal's own elements, and VS Code does not draw it.
- RES-040 cites `claude-code.d.ts` for 2.1.318; 2.1.330 writes `claude-code/index.d.ts` instead.
- The docs' elements table omits `Progress` and `Shader`, which the type file lists.

- UNVERIFIED: an `Svg` graph, an `Image` picture in kitty, Ghostty or iTerm2, and a `Client` region. None was run.
- UNVERIFIED: `classic.FileChanged` under the built-in guard, and its delay. RES-040 found that the guard drops a user's mod's `classic.*` hooks, and no run could seat the guard.
- UNVERIFIED: a board with this repo's real size, about 14 ideas, 9 specs and hundreds of rows. The test used 4 columns of 3 to 12 cards.
- UNVERIFIED: resizing in Desktop and VS Code. VS Code sizes the pane itself and ignores `rows` and `columns`; nothing was run there.
- UNVERIFIED: why Ctrl+X Up did not grow an inline pane past 11 body rows in fullscreen at 100 by 40, where `rows: 30` gave 27 rows in the classic renderer at that size. One run each.

A Bun PTY (`Bun.spawn` with `terminal`) typed the keys and `@xterm/headless` 5.5.0 read the screen. The oracle was the screen and a JSON log the mod wrote from its `ui.render`, `ui.focus`, `ui.scroll`, `classic.FileChanged` and button hooks. `CLAUDE_CODE_NO_FLICKER=0` gave the classic renderer and `=1` fullscreen rendering. The record rests on 18 sessions. The resize runs used a throwaway `CLAUDE_CONFIG_DIR`, so no kept size was written to the user's own config. Source: local test, checked 2026-11-20.
- The type file for 2.1.330 is no longer `claude-code.d.ts`. Claude Code writes `.claude-plugin/types/claude-code/index.d.ts` beside a mod it loads from `--plugin-dir` in an interactive session, with `claude-code-tools/index.d.ts`, `claude-code-mcp/index.d.ts`, `tsconfig.json` and a `.gitignore`, and a `tsconfig.json` at the mod root. Its first line reads "Written by Claude Code 2.1.330." It is 22,469 lines. `claude plugin validate` alone wrote no type file. Source: local test, https://code.claude.com/docs/en/plugins/mods/create#get-type-definitions-for-your-version (last-modified Sat, 21 Nov 2026 00:55:42 GMT), checked 2026-11-20.
- A mod draws only where Claude Code fires `ui.render` for a render site. The two sites a mod fills by itself are `Pane` (terminal, Desktop, VS Code) and `AbovePrompt`, the band above the prompt (terminal, Desktop). `Placed`, a row a mod adds to the transcript, draws in the terminal only. The other sites restyle what Claude Code already draws. Source: https://code.claude.com/docs/en/plugins/mods/reference#render-sites (last-modified Sat, 21 Nov 2026 00:55:51 GMT), checked 2026-11-20.
- A pane is "a sidebar beside the transcript in a wide fullscreen terminal, or a framed region above the prompt otherwise". With several panes open, each gets a tab. In the type file, `placement` is `dock` beside the transcript ("the terminal in fullscreen from 110 columns"), `inline` above the prompt, or `widget` on the Desktop app. Source: https://code.claude.com/docs/en/plugins/mods/interface#pick-where-to-draw (last-modified Sat, 21 Nov 2026 00:55:47 GMT), `Pane` props in `claude-code/index.d.ts` 2.1.330 lines 13803-13884, checked 2026-11-20.
- `$.ui.open(pane: PaneOpenArgs): Promise<UiOpenResult>` opens a pane by `id` (1-64 of letters, digits, `_`, `-`) and takes `title`, `focus`, `closeOnEscape`, `holdToasts`, `backgroundColor`, `rows`, `columns` and `placement: 'widget'`. It resolves `{ isPlaced: true }` or `{ isPlaced: false, reason }`. Opening the pane draws nothing: Claude Code then fires `ui.render` for it. `focus`, `closeOnEscape` and `holdToasts` accept only `true`. Source: `claude-code/index.d.ts` 2.1.330 lines 2923-2951 and 9381-9479, https://code.claude.com/docs/en/plugins/mods/interface#open-a-pane-at-the-right-time, checked 2026-11-20.
- A pane has limited room. A docked pane is at most 45% of the terminal's width and at least 24 columns; `columns` asks for a width inside that cap. An inline pane takes a third of the height by default; `rows` asks for more, "up to what the layout spares". A width or height the user set with Ctrl+X and an arrow wins over both. The VS Code extension ignores `rows` and `columns`. Source: `PaneOpenArgs` in `claude-code/index.d.ts` 2.1.330 lines 9443-9463, https://code.claude.com/docs/en/plugins/mods/interface#open-a-pane-at-the-right-time, checked 2026-11-20.
- Measured pane room: in the classic renderer at 200 by 50 the pane was `inline` with 196 body columns and 14 body rows. At 100 by 40 it had 96 columns and 11 rows, and `rows: 30` gave 27 rows. In fullscreen at 200 by 50 it was `dock` with 77 body columns and 43 body rows, and `e.viewport.columns` read 122, the transcript's width, not 200. `$.ui.open` from a command resolved `{ isPlaced: true }` in 25 of 25 opens across 16 sessions. Source: local test, checked 2026-11-20.
- A pane opened by the mod alone, from a timer or a `turn.start` hook, shows only in a terminal at least 144 columns wide, or 110 after the user opened it once. A pane opened from the user's command or press shows at any width. Source: https://code.claude.com/docs/en/plugins/mods/interface#when-a-pane-waits-for-a-wider-terminal, https://code.claude.com/docs/en/plugins/mods/reference#limits, checked 2026-11-20.
- `$.ui.close({ id })` closes a pane and raises `ui.close` with origin `plugin`, `person` or `unload`. `$.ui.panes()` lists the mod's own open panes as `{ id, title, isShown, isFocused, isPlaced }`, including after a module reload. Source: `claude-code/index.d.ts` 2.1.330 lines 2952-2979 and 19622-19649, checked 2026-11-20.
- `$.ui.view(view: SiteView)` cannot carry a mod's view. It "Puts an agent's transcript in the main view", takes only `{ agentId }` or `{}`, and works only while the call answers the user's own input. Source: `claude-code/index.d.ts` 2.1.330 lines 3051-3067 and 15942-15950, checked 2026-11-20.
- `$.ui.place({ id })` adds one row at the end of the transcript, drawn at the `Placed` site, in the terminal only. It scrolls away with the conversation, Claude does not read it, and `--resume` does not bring it back. One mod can hold 500 placed rows. It requires v2.1.314. Source: https://code.claude.com/docs/en/plugins/mods/interface#place-a-row-in-the-transcript, `claude-code/index.d.ts` 2.1.330 lines 2980-2991, checked 2026-11-20.
- The band, `AbovePrompt`, gives each mod one row in a strip directly above the prompt. It is capped at half the terminal's rows, the prompt included, and scrolls past `maxRows`. The user can collapse it to one row with Ctrl+X Ctrl+A, and the mod cannot expand it again. The band is not drawn in VS Code. Source: `AbovePrompt` props in `claude-code/index.d.ts` 2.1.330 lines 13570-13607, https://code.claude.com/docs/en/plugins/mods/interface#when-the-user-collapses-the-band, https://code.claude.com/docs/en/plugins/mods/reference#render-sites, checked 2026-11-20.
- Elements by app: `Box`, `Text`, `Button`, `Link`, `Code`, `Markdown`, `Input` and `Select` draw in the terminal, Desktop and VS Code. `Svg` draws in Desktop and VS Code only, with a `source` of up to 131,072 characters. `Client` draws in the terminal and Desktop only. `Raster` and `Image` draw in the terminal only. Source: https://code.claude.com/docs/en/plugins/mods/reference#elements, checked 2026-11-20.
- The type file has elements the docs table does not list: `Progress` on every surface, and `Shader` on Desktop and mobile. It also lists a `mobile` surface with `Svg` but no `Client`. Source: `Elements` in `claude-code/index.d.ts` 2.1.330 lines 4803-4893, checked 2026-11-20.
- `Box` is a flex container: `flexDirection` (`row`, `column` and reverses), `flexGrow`, `flexShrink`, `flexWrap`, `alignItems`, `justifyContent`, `gap`, `width` and `height` as a number or a string, `borderStyle`, `backgroundColor`, `position: 'absolute'` with `top`, `left`, `right`, `bottom`, and `display`. Its `overflow` is only `visible` or `hidden`. `overflowX: 'scroll'` scrolls sideways only on a graphical surface; "The terminal and VS Code can't scroll sideways". No `Box` prop scrolls vertically. Source: `BoxProps` in `claude-code/index.d.ts` 2.1.330 lines 1281-1384, checked 2026-11-20.
- A four-column board drew side by side: a row `Box` of four `round`-bordered column `Box`es, each with a title and `Button` cards, in the inline pane (classic renderer, 6 sessions) and the docked pane (fullscreen, 3 sessions). A `Markdown` detail view drew its heading in bold without `#`, its list and its paragraphs, 2 of 2 runs. A `Link` drew only its label "RES-074" in this emulator, 2 of 2 runs, where the gallery says the terminal draws the URL after the label. Source: local test, https://code.claude.com/docs/en/plugins/mods/gallery#link, checked 2026-11-20.
- A tree taller than its pane "scrolls as a whole": the pane body is one window over the whole tree. The window is engine-owned and moved by the wheel, by Up and Down, by Page Up and Page Down, and by Home and End. In a test with 12 cards per column, Page Down moved the whole board by 11 rows to offset 8, the end, and Down there moved nothing, 1 run. Source: https://code.claude.com/docs/en/plugins/mods/reference#render-sites, `SiteScroll` and `Pane.scroll` in `claude-code/index.d.ts` 2.1.330 lines 13866-13874 and 15917-15932, https://code.claude.com/docs/en/keybindings#pane-actions (last-modified Sat, 21 Nov 2026 00:30:21 GMT), local test, checked 2026-11-20.
- A mod can see and redirect each scroll. A `ui.scroll` hook gets `offset`, `by`, `bodyRows`, `contentRows`, `origin`, and for a wheel the body cell under the pointer as `pointer.column` and `pointer.row`; `next({ ...e, offset })` moves the window elsewhere. The type file names the case of "A hook pinning a list over rows it scrolls itself". `$.ui.scroll({ to, in, block })` brings a keyed element or the `start` or `end` of a site into view. Source: `UiScrollArgs`, `UiScrollInput`, `UiScrollPointer` in `claude-code/index.d.ts` 2.1.330 lines 19798-19941 and 2992-3006, checked 2026-11-20.
- One column at a time can scroll. In fullscreen, a mod that drew 4 of 12 cards per column and answered each wheel `ui.scroll` with `{ deny }` and its own offset for the column under `pointer.column` moved only that column. The pane's window stayed at offset 0. Wheel ticks over the first and the last column read `pointer.column` 2 and 62, `by` 3 or -3, 2 of 2 runs. The first wheel-up tick after wheel-downs raised no `ui.scroll` in 3 of 3 sequences; later ticks did. Source: local test, checked 2026-11-20.
- Keys reach a mod only through its controls. "Your mod never reads the keyboard itself": while a pane or the band has focus, Tab moves to the next control, Enter presses the focused `Button` or picks in a `Select`, a `Button`'s `hotkey` (one digit or one lowercase letter) presses it, and Up and Down move between controls while the drawing fits or scroll it when it does not. "A mod can't bind Tab or the arrow keys to anything else". Source: https://code.claude.com/docs/en/plugins/mods/interface#keyboard-focus-and-hotkeys, `ButtonProps.hotkey` in `claude-code/index.d.ts` 2.1.330 lines 1477-1486, checked 2026-11-20.
- In a pane, Left and Right did nothing: they raised no `ui.focus` and no `ui.scroll`, 2 of 2 runs with three presses each. Down from no focus took the first control, Tab took the next, and Up took the one before, in drawing order, 2 of 2 runs. The keybindings page binds Left and Right to next and previous only in the `AbovePrompt` context. Source: local test, https://code.claude.com/docs/en/keybindings#above-prompt-actions, checked 2026-11-20.
- Hotkeys plus `$.ui.focus` give moves in two directions. Buttons with hotkeys `h`, `j`, `k` and `l` called `$.ui.focus` on the card left, below, above or right of the last one; each call resolved `{}`, and Enter then pressed that card, `card-2-1`, which opened its detail view, 2 of 2 runs. A `b` hotkey went back. The mod's own `ui.focus` hook logged no event for its own `$.ui.focus` calls, 0 of 6, while it logged every person move. Source: local test, checked 2026-11-20.
- A pane gets keyboard focus from `$.ui.open` with `focus: true` called from a command or a press, from Ctrl+X Tab, or from a click in fullscreen. Claude Code grants `focus: true` only while the prompt is empty and nothing else holds the keys. In VS Code it grants focus only while the panel has focus, Claude is idle and the prompt box is empty. Source: https://code.claude.com/docs/en/plugins/mods/interface#how-a-pane-gets-keyboard-focus, https://code.claude.com/docs/en/plugins/mods/interface#draw-in-the-vs-code-extension, checked 2026-11-20.
- `$.ui.focus({ requestId, key })` moves the focus ring of the mod's pane or band onto a `Button`, `Input` or `Select` it drew, while that site holds the keys. A `ui.focus` hook sees every move with `element` and `origin` (`person` "by Tab, the arrows or a click", or `plugin`) and can land it elsewhere with `next({ ...e, element })`. The event does not say which key moved the ring. Source: `claude-code/index.d.ts` 2.1.330 lines 3007-3022 and 19275-19379, checked 2026-11-20.
- In VS Code, buttons have no hotkeys: the user clicks or presses Enter on a focused button. VS Code also ignores `Box` `position` and its offsets, `Text` `size`, `mono` and `tabular`, `Input` and `Select` `autoFocus`, and `Svg` `isInteractive`. In a panel 800 pixels or wider a pane docks beside the conversation; narrower, it sits above the prompt box and shows 12 rows before it scrolls. Source: https://code.claude.com/docs/en/plugins/mods/reference#elements, https://code.claude.com/docs/en/plugins/mods/interface#draw-in-the-vs-code-extension, checked 2026-11-20.
- `Markdown({ text, key, dimColor, onLinkPress, pressableLinks })` draws text formatted the way Claude's replies are, in every app. `Link({ href, label })` draws a label and its URL; in Desktop and VS Code it is plain text unless `href` is `https:` or `http://localhost`, and `href` is at most 2,048 characters. `Select({ key, label, options, value, onSelect })` is a dropdown in every app. Source: https://code.claude.com/docs/en/plugins/mods/reference#elements, https://code.claude.com/docs/en/plugins/mods/interface#link-in-the-desktop-app-and-vs-code, https://code.claude.com/docs/en/plugins/mods/gallery (last-modified Sat, 21 Nov 2026 00:55:45 GMT), checked 2026-11-20.
- `Raster({ key, columns, rows, cells })` is a grid of colored character cells in the terminal only: up to 512 columns and 256 rows, 262,144 cells per tree. Each cell is a code point, a color and a background, packed as base64. Each character must be one cell wide, and colors round to a smaller palette. `$.ui.blit` repaints a mounted `Raster`'s cells, or swaps a keyed `Image`'s source, without a new `ui.render`: "up to 120 a second taken, some sixty shown". Source: https://code.claude.com/docs/en/plugins/mods/interface#draw-a-grid-of-colored-cells, https://code.claude.com/docs/en/plugins/mods/reference#limits, `claude-code/index.d.ts` 2.1.330 lines 2789-2809, checked 2026-11-20.
- `Image({ key, source, columns, rows, alt })` draws a PNG or RGBA picture of up to 2 MiB per tree, at most 255 columns and rows, in the terminal only. It draws as a picture only in kitty 0.28 or later, Ghostty, and iTerm2 3.5 or later (iTerm2 from v2.1.305 and only in fullscreen); elsewhere, in GNU screen, in background sessions and in tmux without its requirements, the user sees the dimmed `alt` text. Source: https://code.claude.com/docs/en/plugins/mods/gallery#image-and-client, checked 2026-11-20.
