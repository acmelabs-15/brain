# RES-077: How the mod serves /brain:session

## Question
Can the Brain mod serve `/brain:session`: a plugin command or skill named `session`, whose run the mod takes over to open the views panel with no model turn, or another way?

## Answer
Sufficient answer, each with a local test where the docs and the type file leave it open:

1. Does `$.command.register` refuse a name with a colon, such as `brain:session`, and with what message?
2. A plugin markdown command `session` in the plugin's commands folder: does it show as `/<plugin>:session`; does a `command.run` hook in the same plugin's mod fire for it, and with which name and arguments; can that hook open a pane with `$.ui.open` and end the command so that no model turn starts and no prompt reaches the model?
3. The same for a skill named `session`.
4. Does a `command.describe` hook, or any other documented way, let a mod serve or rename a command as `/<plugin>:<name>`?
5. Does the taken-over command also work while a turn runs, as `immediate: true` does for a registered command?
6. What does the user see in the typeahead and the transcript for each way?
7. What happens when the mod does not load (`--bare`, `disableAllHooks`, or the guard of RES-040): does the markdown command or skill then run as a normal prompt, and what would its text need to say?

Name contrary evidence and what stays unknown. This serves IDEA-015#29, DEC-048 and the spec's command design.

**Yes, the mod can serve `/brain:session`, so DEC-048's name stands.** The plugin ships a markdown command or a skill named `session`. The mod's `command.run` hook on `{ command: 'brain:session' }` calls `$.ui.open` and returns `{}` without `next`. The pane opens, no model turn starts, and nothing of the command reaches the model, then or later. `$.command.register` cannot give the name.

### Answers by point
1. **Colon name: refused.** `$.command.register({ name: 'brain:session' })` throws `brain: $.command.register takes { name, description, argumentHint?, immediate? }; name is letters, digits, _ or - (up to 64)`. The closest registered name is `/brain-session`.
2. **Markdown command: works.** It shows as `/brain:session` with the tag `(brain)`. The mod's `command.run` hook fires with `command: "brain:session"` and `args` as typed, for example `"tasks SPEC-001"`. A hook that opens the pane and returns `{}` ends the run: no `prompt.submit`, no `turn.start`, no request to the model. The saved transcript and the prompt history keep no record of it.
3. **Skill: works the same way.** The name, the arguments, the take-over and the clean result were the same in every test.
4. **No way to rename.** `command.describe` can change only the description, the argument hint and `isHidden`. A rewrite of the name is refused, and no documented call registers or renames a command as `/<plugin>:<name>`. A `prompt.submit` hook with `{ drop }` also stops the turn, but it prints `Prompt dropped by a hook: <reason>` and leaves the typed line in the prompt box. `command.run` is the better seam.
5. **During a turn: it waits.** A typed `/brain:session`, or a key bound to `command:brain:session`, becomes a queued row and runs when the turn ends. Ctrl+X Ctrl+S, send now, runs it at once, but it stopped Claude's turn in the test. Nothing makes a markdown command or skill `immediate`. A mid-turn way exists: the mod also registers a command with `immediate: true`, hides it from the typeahead with `command.describe` `isHidden: true`, and the user binds a key to it. That opened the pane at once during a turn.
6. **What the user sees**: see the table below.
7. **Without the mod: a normal prompt.** Under `--bare` and `disableAllHooks` the typeahead still lists `/brain:session`, and running it starts a model turn. The model reads `<command-name>/brain:session</command-name>`, `<command-args>…</command-args>` and the body with `$ARGUMENTS` filled in. Under the guard's `allowManagedModsOnly` the mod does not load either, by the docs, so the same applies. Where the guard loads and allows the mod, `command.run` passes it, by the guard's source.

| Way | Typeahead | Transcript after a run | Typed during a turn |
|---|---|---|---|
| Markdown command or skill, taken over by the mod | `/brain:session  (brain) <description>` | Nothing; the pane opens | Queued until the turn ends |
| Registered command with `immediate: true` | `/<name>  <description>`, no tag | Nothing; the pane opens | Runs at once |
| The same, hidden with `isHidden: true` | Not listed: `No commands match "/bp"` | Nothing; the pane opens | Runs at once, typed in full or by a key |
| Markdown command or skill, mod not loaded | `/brain:session  (brain) <description>` | The typed line and Claude's reply | Queued, by the docs |

### What the command's text needs to say
The body is read only when the mod did not load, because the take-over skips it. RECOMMENDATION, not tested as wording: the body tells Claude that the views panel needs the Brain mod, which did not load in this session. It names the usual causes: `--bare`, `--safe-mode`, `disableAllHooks`, or an organization policy that allows only managed mods. It tells Claude to say so in one or two sentences and to run no tool, or to give a short text form of the asked view if the spec wants one. The file sets `disable-model-invocation: true`, so Claude never loads it by itself.

### Markdown command or skill
Both take over the same way. A skill's fallback body starts with `Base directory for this skill: <path>`. The plugins reference says "Prefer `skills/` for new plugins", while Brain's manifest already lists `./.claude/commands`. The spec can pick either; the test gives no reason to prefer one.

### Contrary evidence
- The skills page says a plugin skill also runs by its bare name, `/fancy` for `/my-plugin:fancy`. In the test, `/session status` printed `Unknown command: /session` for both the skill and the markdown command.
- `command.describe` fires before `session.start`. A description set from start-time state needs `$.ui.invalidate('command.describe')`.
- Send now runs a queued `/brain:session` at once, but it stops a turn in which Claude is only writing.

### What stays unknown
- UNVERIFIED: the take-over in fullscreen rendering, the Desktop app and the VS Code extension. Only the classic renderer in the terminal ran.
- UNVERIFIED: what a hook should do when `$.ui.open` resolves `{ isPlaced: false }`, for example in `claude -p`. Calling `next(e)` there should run the body as the fallback; no run checked it.
- UNVERIFIED: a run where the guard is seated on a managed machine. RES-040 could not seat it.
- UNVERIFIED: whether Claude can still invoke the skill through the Skill tool with `disable-model-invocation: true`, and whether that path fires `command.run`. The docs say the field stops Claude from loading it.
- Each behavior rests on 1 or 2 runs.

## Findings
- Method and capability check: I loaded brain:source-driven-development through the Skill tool. WebFetch answered a real read of https://code.claude.com/docs/en/plugins/mods/api. `curl` of each docs page's `.md` form gave the full text that the findings cite, with its `last-modified` header. `brain sdd-cache lookup` does not exist in the Brain CLI 0.13.0 ("unknown command: sdd-cache"). Firecrawl was not needed. Source: local run, checked 2026-11-21.
- A registered command's name allows letters, digits, `_` and `-`, up to 64 characters, and "the person runs it as `/<name>`". Source: `CommandSpec` in the 2.1.330 type file `claude-code/index.d.ts` lines 2307-2330, https://code.claude.com/docs/en/plugins/mods/reference#limits (last-modified Sat, 21 Nov 2026 05:26:36 GMT), checked 2026-11-21.
- `$.command.register` "throws for a taken name, with a message such as `"/focus" refused: it is the built-in /focus`". A hook that throws is skipped, so the rest of the `session.start` hook does not run. Source: https://code.claude.com/docs/en/plugins/mods/api#add-a-command (last-modified Sat, 21 Nov 2026 05:33:03 GMT), checked 2026-11-21.
- A plugin's markdown command and skill carry the plugin's name as a prefix. A `commands` map key `about` in plugin `deploy-tools` "runs as `/deploy-tools:about`", and `my-plugin/skills/review/SKILL.md` becomes `/my-plugin:review`. "The bare `/fancy` also invokes the skill unless another command already uses that name." The plugins reference lists `commands/` as "Flat Markdown command files. Prefer `skills/` for new plugins". Source: https://code.claude.com/docs/en/plugins-reference#commands (last-modified Sat, 21 Nov 2026 05:41:10 GMT), https://code.claude.com/docs/en/skills#how-a-skill-gets-its-command-name (last-modified Sat, 21 Nov 2026 05:26:54 GMT), checked 2026-11-21.
- `CommandSource` is `builtin`, `plugin`, `user` or `mcp`, and "`plugin` is a plugin's markdown command, skill or `$.command.register`". `$.command.list()` names the plugin "that registered it, or whose manifest carries it". Source: `CommandSource` and `CommandInfo` in `claude-code/index.d.ts` 2.1.330 lines 2139-2160 and 2295-2302, checked 2026-11-21.
- `command.run` "Fires when a slash command is about to run (`/name args` typed, or a plugin's `$.command.run`)". A hook can "return `{ text }` without it [`next`] to answer in its place; one after `next` replaces a printed output, not a panel or prompt it opened". The result type adds: "A hook's own answer without `next` runs no command". Source: `command.run` in `EventInputs` and `CommandRunResult` in `claude-code/index.d.ts` 2.1.330 lines 2231-2247 and 5401-5414, checked 2026-11-21.
- `command.run`'s input names the command "without its slash (`compact`, `hello`), aliases and folds resolved", and "A rewrite is refused". `args` is "Everything after the name, as typed". `origin` reads `composer` for the user's Enter, and `presentation` gives `isFullscreen` and `columns`. Source: `CommandRunInput`, `CommandPresentation` and `PromptOrigin` in `claude-code/index.d.ts` 2.1.330 lines 2171-2229 and 11928-11940, checked 2026-11-21.
- `command.describe` fires once per command for the typeahead and `/help`. A hook can change only `description`, `argumentHint` and `isHidden`; "the name, `immediate` and `provider` stay as they were", and a rewrite of `command` is refused. A hidden command "still runs when typed in full". Answers are cached until `$.ui.invalidate("command.describe")`. Source: `CommandDescribeInput`, `CommandDescribeResult` and `command.describe` in `claude-code/index.d.ts` 2.1.330 lines 2095-2137 and 5415-5426, checked 2026-11-21.
- `immediate` on `command.describe` is read only: "Whether the command declares it runs at once when typed mid-turn ... One that decides per invocation reads false." The skill frontmatter table has no field for it. Source: `claude-code/index.d.ts` 2.1.330 lines 2118-2125, https://code.claude.com/docs/en/skills#frontmatter-reference, checked 2026-11-21.
- "If you send a command while Claude is responding, Claude Code queues it and runs it after the current turn finishes. Claude Code runs some commands immediately ..." A registered command runs mid-turn only with `immediate: true`. Source: https://code.claude.com/docs/en/commands (last-modified Sat, 21 Nov 2026 05:59:30 GMT), https://code.claude.com/docs/en/plugins/mods/interface (last-modified Sat, 21 Nov 2026 06:03:21 GMT), checked 2026-11-21.
- `prompt.submit` carries `command` when the submission runs a slash command, and "A `{ drop }` stops a skill or prompt command before it is rendered". Its `text` is "a slash command's line as `command.run` left it", so `command.run` comes first. Source: `PromptSubmitCommand` and `PromptSubmitInput` in `claude-code/index.d.ts` 2.1.330 lines 12186-12230, checked 2026-11-21.
- `skill.prompt` "Fires when the engine expands a skill's prompt for the model (`/name`, the Skill tool, a preload)". A hook can only change the text the model reads. Source: `skill.prompt` in `claude-code/index.d.ts` 2.1.330 lines 5477-5487, checked 2026-11-21.
- For each skill or command that Claude can invoke on its own, its name and description are in Claude's context on every turn. `disable-model-invocation: true` stops Claude from loading a skill by itself. Source: https://code.claude.com/docs/en/plugins#what-an-enabled-plugin-adds-to-your-sessions (last-modified Sat, 21 Nov 2026 05:44:36 GMT), https://code.claude.com/docs/en/skills#frontmatter-reference, checked 2026-11-21.
- The built-in diff mod serves its own registered `/diff` from a `command.run` hook on `{ command: 'diff' }` that returns `{}` or the toggle's result, and calls `next(e)` first in a hook on `{ command: ['clear', 'resume'] }`. Its README says a session "where another `/diff` is listed leaves the plugin idle", and that from the first docked open `/diff` "runs at once even while" a turn runs. Source: https://github.com/anthropics/claude-code/blob/b215e8e6b1de769d89cf88163b47dd01681a9d2c/mods/diff/hooks/register.ts lines 1084-1100 and 1262-1270, https://github.com/anthropics/claude-code/blob/main/mods/diff/README.md lines 3-10 and 128, checked 2026-11-21.
- Where the built-in guard loads, `command.run` passes it, by the guard's source. `--bare` and `disableAllHooks` load no hooks module of a user's plugin. Source: docs/research/RES-040-ui-ask-opening-question.md:18, :48 and :49, checked 2026-11-21.
- An organization's `allowManagedModsOnly` makes Claude Code refuse a mod the user installed, with the debug line `mods are limited to your organization's by policy (allowManagedModsOnly)`. `--safe-mode` "turns installed mods off". Source: https://code.claude.com/docs/en/plugins/mods/troubleshoot (last-modified Sat, 21 Nov 2026 05:38:18 GMT), https://code.claude.com/docs/en/plugins/mods/admin#stop-user-installed-mods-from-loading (last-modified Sat, 21 Nov 2026 06:03:21 GMT), checked 2026-11-21.
