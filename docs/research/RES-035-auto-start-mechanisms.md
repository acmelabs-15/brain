# RES-035: Mechanisms that run using-brain at session start

## Question
Which mechanisms can a plugin use, on each host, to run the `using-brain` skill at session start with no user setup?

## Findings
- Test method: every "local test" below ran on Claude Code 2.1.318 unless it names another host, with a throwaway plugin from `--plugin-dir`, `--setting-sources project` and the haiku model, one run per case unless it gives a count. Interactive runs used `expect` in this repo, a trusted folder, and the oracle was a hook log of `UserPromptSubmit` and `Stop`. No marketplace install was tested. Source: local test, checked 2026-11-05.
- Today brain's `SessionStart` hook prints protocol text, the `brain` path and the status, and `protocol/PROTOCOL.md` does not name `using-brain`. Source: scripts/hooks/session-start.ts:136, protocol/PROTOCOL.md (`grep using-brain` finds nothing), checked 2026-11-05.
- Claude Code installed here is 2.1.318. Source: output of `claude --version`, checked 2026-11-04.
- A `SessionStart` hook runs on five sources: `startup`, `resume`, `clear`, `compact` and `fork`. Only `command` and `mcp_tool` handlers are supported on it. Source: https://code.claude.com/docs/en/hooks#sessionstart, checked 2026-11-04.
- A `SessionStart` hook returns these event fields: `additionalContext`, `initialUserMessage`, `sessionTitle`, `watchPaths` and `reloadSkills`, plus the universal fields `continue`, `stopReason`, `suppressOutput`, `systemMessage` and `terminalSequence`. It has no decision control and no field that loads a skill or calls a tool. Source: https://code.claude.com/docs/en/hooks#sessionstart-decision-control, checked 2026-11-04.
- `additionalContext` reaches Claude as a system reminder before the first prompt. The host enforces the delivery, but the text only asks the agent to act. Text framed as a system command can trigger prompt-injection defenses, so the docs ask for factual statements. Source: https://code.claude.com/docs/en/hooks#add-context-for-claude, checked 2026-11-04.
- `additionalContext`, `systemMessage`, `initialUserMessage` and plain stdout are each capped at 10,000 characters. A longer string goes to a file, Claude gets a 2,000-character preview, and nothing asks Claude to read the file. Source: https://code.claude.com/docs/en/hooks#json-output, checked 2026-11-04.
- `skills/using-brain/SKILL.md` is 20,227 bytes, so its full text does not fit in one `additionalContext` string. Source: skills/using-brain/SKILL.md (`wc -c`), checked 2026-11-04.
- `initialUserMessage` becomes the first user message only in non-interactive mode with `-p`, by the docs. A plugin hook that sets it must be installed before the session starts. Source: https://code.claude.com/docs/en/hooks#sessionstart-decision-control, checked 2026-11-04.
- The test agrees: in `-p` with no prompt, `initialUserMessage` started a turn and the agent called the Skill tool. In an interactive session it started no turn. Source: local test, checked 2026-11-05.
- `reloadSkills` re-scans skill folders after the hooks finish, so a hook can install a skill for the same session. It does not load a skill into the conversation. It arrived in 2.1.152. Source: https://code.claude.com/docs/en/hooks#reload-skills-that-a-hook-installs, https://code.claude.com/docs/en/changelog, checked 2026-11-04.
- The `Setup` event fires only with `--init-only`, or with `--init` or `--maintenance` in `-p` mode, never on a normal start. Claude Code discards its JSON output, so it cannot reach the conversation. It arrived in 2.1.10. Source: https://code.claude.com/docs/en/hooks#setup, https://code.claude.com/docs/en/changelog, checked 2026-11-04.
- `UserPromptSubmit` runs before Claude reads each prompt, on any wording, and also on scheduled tasks, background subagent reports and messages from other sessions. It can add `additionalContext`, set `sessionTitle` or block the prompt, but it cannot replace the prompt. Its default timeout is 30 seconds. Source: https://code.claude.com/docs/en/hooks#userpromptsubmit, https://code.claude.com/docs/en/hooks#decision-control, checked 2026-11-04.
- `InstructionsLoaded` only observes: Claude Code discards its JSON output. Source: https://code.claude.com/docs/en/hooks#instructionsloaded-decision-control, checked 2026-11-04.
- `PreToolUse` with `permissionDecision: "deny"` prevents a tool call, and the reason reaches Claude. The host enforces this. The hook fires only when Claude calls a tool. Source: https://code.claude.com/docs/en/hooks#pretooluse-decision-control, checked 2026-11-04.
- A `Stop` hook with `decision: "block"` or `additionalContext` keeps the turn going, and the `reason` tells Claude why. Loop protection is the `stop_hook_active` input and a cap of 8 consecutive continuations. The host enforces the continuation; what Claude does next stays its own choice. Source: https://code.claude.com/docs/en/hooks#stop-decision-control, checked 2026-11-04.
- A plugin gate of `PreToolUse` deny plus `Stop` block made the agent call the Skill tool in 2 of 2 `-p` runs, one of them with the prompt "Do not call any tool". The cost was extra turns, a visible hook error, and in the text-only run the reply came before the skill. Source: local test, checked 2026-11-05.
- A loaded skill is not a followed skill: in one gate run the agent read the skill, then refused its instruction, saying it "came from the tool output, not from you". Source: local test, checked 2026-11-05.
- An `asyncRewake` command hook runs in the background and wakes Claude on exit code 2, even when the session is idle. Its stderr, or else its stdout, reaches Claude as a system reminder. A `-p` run kills it at teardown. Source: https://code.claude.com/docs/en/hooks#command-hook-fields, https://code.claude.com/docs/en/hooks#limitations, checked 2026-11-04.
- A plugin `SessionStart` hook with `asyncRewake: true` and exit 2 started a turn with no user input on `startup`, `clear` and `compact` in interactive sessions, and the agent ran the skill in 5 of 5 wakes. The host starts the turn, but the load stays the agent's choice. The agent receives the text under the label "Stop hook blocking error from command". Source: local test, checked 2026-11-05.
- When a first prompt arrived 1 second after start, the `asyncRewake` wake and the user's prompt shared one turn, and the agent ran the skill and answered the prompt. Source: local test, checked 2026-11-05.
- `prompt` and `agent` hook types do not run on `SessionStart` or `Setup`, and they run in a separate model call, not in the main conversation. Source: https://code.claude.com/docs/en/hooks#prompt-based-hooks, checked 2026-11-04.
- An `mcp_tool` hook on `SessionStart` at launch, including `--continue` and `--resume`, is skipped because the MCP servers are not yet available. It runs after `/clear` or a compaction. Source: https://code.claude.com/docs/en/hooks#mcp-tool-hook-fields, checked 2026-11-04.
- A skill can carry its own hooks in frontmatter, but they register only after the skill is invoked, so they cannot start the skill. Source: https://code.claude.com/docs/en/hooks#hooks-in-skills-and-agents, checked 2026-11-04.
