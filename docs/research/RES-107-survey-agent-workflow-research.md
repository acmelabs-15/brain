## Question

## Answer

### Where the sources agree
- One lead plans and writes; workers search and return a short digest, not raw pages. S2, S4, S5, S6, S7 and S14 all do this.
- Research size has tiers, and the lowest tier starts no extra agent. S4, S6, S13, S15 and the adjacent cookbook prompts say this in almost the same words.
- Each claim carries its source, a gap is a valid result, and a claim with no source gets a label ("ASSUMPTION", "UNVERIFIED", "unverified").
- The model's memory is a lead, not evidence (S4, S5, S10, S13, S14).
- Primary or official sources come first (S1, S4, S5, S10, S15).
- Fetched text is data, not instructions (S3, S6, S10, S12).
- Research workers run one tier below the lead when a model is named at all: sonnet in S2, S5 (balanced) and S7, "mid-tier" in S6, "one tier down" in S4.
- For code, the citation is file and line, and a search agent runs before a reading agent (S2, S4).

### Where the sources disagree
| Topic | One side | Other side |
|---|---|---|
| Number of agents | Small and capped: 1 (S1), 2 to 6 (S2), 2 to 3 (S7), preset 2, 3 or 6 with a "3–5 sweet spot" (S4) | Fixed 4 (S5); one per unknown with no cap (S3); "Always the maximum roster" (S14) |
| Where the human stops the run | Before research, on the plan or the questions (S2, S4, S5) | After research (S7); no stop at all (S3, S6, S1) |
| Recommendation in the result | Forbidden; describe only (S2, S4 code mode, S3 `assess`) | Required: "Use X because Y" (S5); allowed (S7) |
| What the researcher may know | Only the questions, never the goal (S2, S4) | The planning context summary and settled decisions (S6); project files (S5) |
| Stored research | Search it first, with age rules (S6, S5 cache, S4 refresh) | Do not load it unless the ask names it (S4 code mode); delete it (S1 doc); S2 removed its search step |
| Check step | Fresh agent as results land (S4); a second team after (S14) | Self checklist (S5, S11, S12); none (S1, S2, S3 plan, S7) |
| Agent type for a worker | Only fixed named agents; generic types forbidden (S2) | Only a generic subagent with a prompt file; named specialists forbidden (S6) |
| Where the brief sits | Agent definition (S2, S5, S7) | Reference files in the skill (S4, S6, S14); one line in the command (S3) |
| Model for workers | Mid tier, since research "follows explicit instructions" (S5) | "a capable model at high reasoning effort" (S14); lowest effort for locators and verifiers (S4) |
| Source count | Fixed numbers: 15 to 30 (S12), 10+ and 3 per major claim (adjacent 199 skill) | By risk of the claim: load-bearing claims only at the normal level (S4), critical claims (S5) |

Evidence against popular claims:
- "More agents give better research." S1 records a duplicate agent that cost about 450k tokens. S4 names 3 to 5 as the useful range. The cookbook prompt says "More subagents = more overhead". Only S14 asks for the maximum, and only on an explicit user order.
- "Save research in the repo so later sessions use it." S1's own doc says nothing loads the file and a stale file is worse than none. S4 says a document in context "gets repeated whether or not it still holds". S2 dropped its search of stored notes.
- "Check the whole report at the end." S4 says end-of-run rewrites make reports worse and checks each part as it lands. S4 gives no data for this.

### Worth a deep run
1. **S4 BMAD `bmad-deep-recon`.** It is the one source that answers all nine questions in one skill: presets, a plan stop, the research firewall, check levels, refresh by age, a model rule, and a separate code mode. The pack files, `synthesis.md`, `selection.md` and the `recon_kit.py` script were not read.
2. **S6 compound engineering, `ce-plan` research and the learnings researcher.** It has the most complete rule for "research or not", routes by intent, and is the best source on stored research (stale mark, conflict rule). `repo-research-analyst.md` and the refresh skill that sets the stale mark were not read.
3. **S2 humanlayer, the question and research split, with its history.** Two sessions keep the goal away from the researcher. The repo also shows what the makers removed over a year (stored-notes search, the opus lead) and holds an eval folder for a documentation researcher that was not read.
4. **S5 GSD Core, the parts in code.** A research cache with lifetimes, a confidence tier from code, a gate on open questions and a model table are rules that code enforces, not prose. The 46 KB phase researcher and the 98 KB plan workflow were not read.
5. **Topic: stop rules and the cost of too much research.** S14 (waves until three bring nothing new, claim graph, second team) and S1 (no stop rule, a recorded failure) are the two ends. A deep run can compare the stop rules of S4, S6, S13 and S14.

### S1. mattpocock/skills: `research` skill
- The repository exists and is active (default branch `main`, last push 2026-11-19). Source: https://github.com/mattpocock/skills, checked 2026-11-21.
- The whole skill is three steps for one background agent with a fresh context: investigate against primary sources (official docs, source code, specs, first-party APIs), write one Markdown file that cites each claim, and save it where the repo keeps such notes. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/skills/engineering/research/SKILL.md, checked 2026-11-21.
- The skill sets no agent count, no stages, no check step, no stop rule, no model and no human gate. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/skills/engineering/research/SKILL.md, checked 2026-11-21.
- The maintainer's own doc says the skill has no allowlist, no domain gate and no verification pass; "the model" decides what a high-trust source is, and the reader must follow two or three citations by hand. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/docs/engineering/research.md, checked 2026-11-21.
- The same doc states "The skill has no stopping criterion" and reports two results of that: agents that go too deep, and agents that miss the one detail that mattered. It tells the user to set a narrow question. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/docs/engineering/research.md, checked 2026-11-21.
- The same doc records an open bug (issue #530): the background agent starts a second research agent, and one reporter measured about 450k tokens across three overlapping runs. No fix is shipped. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/docs/engineering/research.md, checked 2026-11-21.
- The same doc says no later session loads a past research file, that "a stale one is worse than none", and that the community view is to keep ADRs and to archive or delete research files. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/docs/engineering/research.md, checked 2026-11-21.
- The same doc limits the skill to facts from outside the working directory and sends "does this work in my code base" to a `prototype` skill and decisions to a grilling skill. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/docs/engineering/research.md, checked 2026-11-21.
- The same doc says the `wayfinder` skill starts one `/research` subagent per research ticket in parallel, with no wait for the human, in changes not yet released. Source: https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/docs/engineering/research.md, checked 2026-11-21.

### S4. bmad-code-org/BMAD-METHOD: `bmad-deep-recon` skill
- The repository exists (last push 2026-11-22 UTC). Source: https://github.com/bmad-code-org/BMAD-METHOD, checked 2026-11-21.
- The skill has four services: Draft (write a prompt for the user's own deep-research tool), Process (turn a finished report into a cited summary), Run (research here with parallel web agents) and Codebase (research the repository). Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/SKILL.md, checked 2026-11-21.
- Size is a preset with three knobs: quick (2 subagents, 5 sources per round, 1 round), standard (3, 8, 2) and deep (6, 12, 3). The user's words in the request override the preset. Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/references/run.md, checked 2026-11-21.
- The plan also picks a "decomposition topology": breadth-first (agents split the sub-questions), depth-first (agents split by angle on one question) or straightforward (one agent, no fan-out, "never overinvest in a simple query"). Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/references/run.md, checked 2026-11-21.
- The human gate is one "plan gate" before research: the decision, the dimensions, the topology, the knobs, the search tools and a time estimate, shown as a checklist for approval. After it, each dimension ends with a one or two line checkpoint and the run continues unless the user speaks. Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/references/run.md, checked 2026-11-21.
- Headless mode asks nothing, skips checkpoints, logs each judgement as an assumption and ends with a JSON status. Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/SKILL.md, checked 2026-11-21.
- Loop: each dimension runs in rounds, broad first, then follows leads; contradictions get priority. A dimension stops on coverage or on "novelty exhaustion" (a full round with no new load-bearing claim or lead). A "stop-and-write valve" ends a run that goes well past its estimate. Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/references/run.md, checked 2026-11-21.
- Brief: each agent gets its questions, the decision, its search tools, preferred and banned sources, a source-quality card, a source budget and a tool-call budget (under 5 for a simple lookup, 20 never exceeded), query rules and a return contract (claims with source, publisher, publication date, access date, confidence, class, plus leads and what it could not find). Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/references/run.md, checked 2026-11-21.
- The "research firewall": project context shapes the questions but is not evidence, and a research subagent receives only its brief, with no project files. Source: https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/core-tools/bmad-deep-recon/SKILL.md, checked 2026-11-21.
