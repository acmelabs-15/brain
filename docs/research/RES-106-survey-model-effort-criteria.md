# RES-106: Survey: criteria for an agent's model and effort level

## Question
Survey, area 5 of 5: which criteria and tools exist for the choice of model and effort level for an agent's task, for the eight survey questions?

## Answer
This is a map of 23 sources in 21 table rows. It is not a recommendation for our design. In this record, "effort level" means the reasoning or thinking level of a model. It does not mean the glossary's Effort.

### hyper.charm.land
Hyper is a paid inference service from Charm, the maker of the Crush coding agent. It serves open-weight coding models through endpoints that Claude Code, Codex and other agents can use. It bears on the question in one part only: its router, Prism.

- **What Prism is.** Prism is a routing model with 8B parameters. It reads each request and sends it to one of Hyper's own models. The user selects Prism in place of a model.
- **What it uses.** The stated criterion is task difficulty against cost. Hyper states no method.
- **What it does not do.** It does not select an effort level. It does not route to Claude, GPT or Gemini models. It gives no rule that an agent can read and apply.
- **Evidence.** One vendor figure: "cost savings around 45%". No quality figure.
- **Maturity.** Young. A Crush release put Hyper in private beta on 1 May (year not shown). The FAQ shows new plans and a training-data rule that starts on 2026-10-15. No version or launch date is stated.
- **Fit.** Hyper is a router service, so it is one example of the "automatic router" form. It does not fit a skill that must give an agent criteria, because the choice is made outside the agent and only for Hyper's models.

### Where the sources agree
- **Same four criteria.** Difficulty, need for speed, cost, and the size or length of the work appear in every maker's guide.
- **Checkable output permits a small model.** OpenAI says "when you know what a good result looks like". Anthropic says "checkable outputs". This is a criterion apart from difficulty.
- **The level names are not comparable.** All three makers say that levels and defaults differ by model. Anthropic says the scale is "calibrated per model".
- **Measure, then choose the lowest level that holds.** Anthropic, OpenAI and Google all point to the user's own evals. None gives figures on the level pages.
- **The top level is seldom worth its cost.** Anthropic, OpenAI ("Most tasks do not need Max or Ultra"), the preprint and Vals AI agree.
- **A sub-agent inherits by default.** Claude Code, Codex, Gemini CLI, Antigravity, Cursor and Amp all give a sub-agent the parent's model unless a definition sets one.
- **Sub-agents cost more tokens.** Anthropic, OpenAI and Cursor state it.
- **Guidance dies with each release.** Each maker ties its advice to named models and says to test again.

### Where the sources disagree
- **A cheap model for sub-agents.** Anthropic's table and effort page give sub-agents the smallest model and the `low` level. Hyper's setup page and Cursor's Explore do the same. Anthropic's own measurement goes against it for coding: Haiku sub-agents lost about 4 points and did no better than a lower effort level. Claude Code runs its own Explore sub-agent on the `opus` alias.
- **Lead and sub-agent split.** The 2025 post reports +90.2% for an Opus lead with Sonnet sub-agents. The current page says delegation won only for fan-out work and work above one context window. In every other measured case one model at a lower effort level won.
- **The effort level for search.** The general table says `low` for sub-agents. The Opus 4.7 block says `xhigh` for "detailed web search". The Haiku 5.5 block says the model skips searches at `low`.
- **Model or effort level first.** Anthropic: "Tuning effort is often a better lever than switching models." OpenAI: "a tuning knob, not the primary way to recover quality." The 2025 post: a model upgrade gave more than a doubled token budget.
- **Start low or start high.** The October preprint says start lowest and escalate after a verified failure. Google says "Start with `high` for most complex tasks". The July preprint found xHigh much better for a correct first try, on a small sample.
- **Routers.** Vendors report 45% to 85% cost cuts. LLMRouterBench found that routers do not reliably beat a simple baseline. OpenRouter's own page shows its routers below a fixed model on at least one of five benchmarks. Antigravity says its default option "isn't a router that classifies your prompt upfront".
- **Defaults.** Claude Code and the Claude API state different default levels for the same models.

### Worth a deep run
1. **Anthropic's cost and intelligence page.** It is the only maker source with measured criteria for when to delegate and to which model. About half of the page was not read.
2. **The settings on each host.** Claude Code, Codex, Cursor and Antigravity differ in what a definition can set and in what a user's environment overrides. A skill can only apply criteria that the host lets it set. Antigravity has no effort level field for a sub-agent.
3. **The October preprint and the Vals AI study.** Together they are the measured basis for a rule such as "start low, escalate after a verified failure". Only the abstract of the preprint was read.
4. **Effort level for search and read work.** The makers' statements conflict here, and this is the exact case of a research sub-agent. The per-model prompting guides that the effort page links may settle it.
5. **Routers that also select the effort level.** OpenRouter's Auto Router is the one example. LLMRouterBench is the counter-evidence. A deep run can decide whether routers are out of scope.

### Not reached
- The last part of three long Anthropic pages: sub-agents (about 15,000 characters), model configuration (about 35,000) and cost and intelligence (about 96,000).
- The full text of the three papers. Only the abstract pages were read.
- Hyper's launch date, a Prism documentation page, and any quality measurement of Prism. None was found.
- UNVERIFIED: Not Diamond and Martian as routers; maker posts from Cognition; Anthropic's blog post "The advisor strategy". None was checked.
- UNVERIFIED: forum reports that Cursor and Codex sub-agents do not always run on the model that a definition sets.
- Most pages came through a fetch tool that summarizes with a small model. A deep run must check each quote against the raw page. The Hyper pages, the Anthropic model choice guide, the Anthropic effort page and the Claude Code advisor page were read as raw text.

## Findings
### Hyper (Charm)
- Hyper is an inference service from Charm for open-weight coding models. Its page says: "Build your next thing with coding-optimized, high availability, cost-efficient open source inference, and the platform to power it". Source: https://hyper.charm.land/, checked 2026-11-21.
- Hyper includes an automatic model router with the name Prism. The page says: "Prism is a decision model, with a full 8B parameter backbone, which reads the prompt like an LLM. It analyzes tasks and routes them to the most appropriate Hyper model for the job". Source: https://hyper.charm.land/, checked 2026-11-21.
- Prism routes only between the open-weight models that Hyper serves (the page lists models from DeepSeek, Moonshot, Alibaba and Z.AI). It has three cuts (Prism, Prism Core, Prism Flash) that limit "how far up the roster each request may reach". Source: https://hyper.charm.land/, checked 2026-11-21.
- Prism's stated criterion is task difficulty against cost: "Renaming a var is not the same as hunting down a deadlock... often the best models for the job are the small, fast ones." Its only stated measurement is "We typically see cost savings around 45%", with no method and no quality figure. Source: https://hyper.charm.land/, checked 2026-11-21.
- Prism costs a routing fee of "$0.10 /M Input + Cache Hit + the price of the model it picks". Source: https://hyper.charm.land/, checked 2026-11-21.
- Charm states that Prism is "constantly re-trained as new, capable models arrive" and is trained "on real sessions". Source: https://hyper.charm.land/faq, checked 2026-11-21.
- Hyper works as an API endpoint for Claude Code, Codex and other agents through `/v1/chat/completions`, `/v1/responses` and `/v1/messages`. A user selects Prism in place of a model name; the service makes the choice for each request. Source: https://hyper.charm.land/ and https://hyper.charm.land/docs, checked 2026-11-21.
- The Hyper pages do not state an effort or thinking level choice, a role split between lead agent and sub-agent, a launch date, or a version. The FAQ shows recent plan changes: a retired free plan, a retired "original Shred plan", and "nothing submitted before October 15, 2026 will be used for training". Source: https://hyper.charm.land/faq, checked 2026-11-21.

### Anthropic: Claude API docs
- The model choice guide names four criteria: capabilities, speed, cost and effort. It says: "Tuning effort is often a better lever than switching models". Source: https://platform.claude.com/docs/en/about-claude/models/choosing-a-model, checked 2026-11-21.
- The guide gives two start methods. Efficiency-first starts with Claude Haiku 5.5 and upgrades "only if necessary for specific capability gaps". Capability-first starts with Claude Opus 5.5, then lowers effort or the model, and moves to Claude Fable 5.2 "if your evals at `xhigh` or `max` effort still fall short". Source: https://platform.claude.com/docs/en/about-claude/models/choosing-a-model, checked 2026-11-21.
- The guide has a four-row selection table. It gives "multistep deep research" as an example for Claude Fable 5.2 and "subagent tasks" as an example for Claude Haiku 5.5. It says: "Most workloads start with Claude Opus 5.5". Source: https://platform.claude.com/docs/en/about-claude/models/choosing-a-model, checked 2026-11-21.
- The guide makes a task-specific test set the basis of the choice: "Having a good evaluation set is the most important step in the process". Source: https://platform.claude.com/docs/en/about-claude/models/choosing-a-model, checked 2026-11-21.
- The effort parameter has five levels: `low`, `medium`, `high`, `xhigh`, `max`. It affects all output tokens, which includes tool calls: "Lower effort also means fewer and terser tool calls". Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- The effort table gives a typical use for each level. `low`: "Simpler tasks that need the best speed and lowest costs, such as subagents". `xhigh`: "Long-running agentic and coding tasks (over 30 minutes) with token budgets in the millions". Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- The effort page warns that low effort harms search work on the small model. For Claude Haiku 5.5: "In long agent prompts, the model is more likely to skip a search, stop early, or skip a check at `low`". Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- For Claude Opus 4.7 the effort page recommends `xhigh` for "exploratory tasks such as repeated tool calling, detailed web search, and knowledge-base search". This disagrees with the general table row that puts sub-agents at `low`. Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- The effort page says that `max` gives small gains: "On most workloads `max` adds significant cost for relatively small quality gains, and on some structured-output or less intelligence-sensitive tasks it can lead to overthinking". Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- The effort page tells the reader to measure again for each model: "Run an effort sweep on your own evals rather than carrying settings over" from the earlier model. The page keeps one recommendation block per model. Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- On the API, effort is the request field `output_config.effort`. On Managed Agents it is `effort` on the agent's model object. A change of the top-level effort between requests "can invalidate all or part of the prompt cache". Source: https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.
- Anthropic documents two patterns that combine models: an advisor (a smaller model runs the loop and consults a frontier model) and an orchestrator (a frontier model plans and lower-cost sub-agents do the bulk work). Source: https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence, checked 2026-11-21.
- The same page says to tune one model before a second model is added: sweep effort first, and build a pairing only if it beats the single model's score-against-spend curve. Source: https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence, checked 2026-11-21.
- The page gives the delegation criteria from measurements on earlier models. Delegation came out ahead for routine work with a long cost tail and for work larger than one context window. When the work is one dependent chain or fits in one context, the orchestrator's model alone at lower effort came out ahead in every measured case. Source: https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence, checked 2026-11-21.
- The page reports on an internal defect-search benchmark that Opus 5.5 with Sonnet 5.5 sub-agents "matches Opus 5.5 alone, at medium, for about a third less". Source: https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence, checked 2026-11-21.
- The page reports evidence against the cheapest model for sub-agents in coding. Opus 5.5 at `medium` with Haiku 5.5 sub-agents cut cost per attempt by 32%, but the pass rate fell about 4 percentage points, about what lower effort without sub-agents gives at that cost. Source: https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence, checked 2026-11-21.
- The page reports advisor failures. On one benchmark the pairing scored 7 points below the executor alone, and the executor consulted the advisor on 1 of 300 tasks. The page says: "An advisor can help only when the executor consults it." It also says to recheck at every model release. Source: https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence, checked 2026-11-21.

### Anthropic: Claude Code docs
- A Claude Code sub-agent definition has a `model` field. It accepts an alias (`sonnet`, `opus`, `haiku`, `fable`), a full model ID, or `inherit`. Without the field, the sub-agent runs on the model of the conversation that starts it. Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- Claude Code resolves a sub-agent's model in this order: the per-invocation `model` parameter, the `model` field of the definition, the `CLAUDE_CODE_SUBAGENT_MODEL` environment variable, the main conversation's model. Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- `CLAUDE_CODE_SUBAGENT_MODEL` with `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` applies one model to every sub-agent. In that state Claude Code ignores the `model` field of definitions, so a plugin's choice does not apply. Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- A sub-agent definition has an `effort` field with the options `low`, `medium`, `high`, `xhigh`, `max`; "available levels depend on the model". Claude can also pass an `effort` parameter for one invocation. The `CLAUDE_CODE_EFFORT_LEVEL` environment variable takes precedence over both. Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- A sub-agent on a model other than the main conversation's model does not get the session's effort level: "On another model, that level doesn't apply. To choose its level, set the `effort` field". Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- The built-in sub-agents show role defaults. Plan and General-purpose inherit the parent's model. Explore runs on the model of the `opus` alias on Anthropic accounts. `claude-code-guide` and `web-fetch` run on Haiku. The docs suggest a custom `Explore` with `model: haiku` "to run exploration on a lower-cost model". Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- The sub-agent page gives no criteria for which model fits which task. Its one statement is that sub-agents help to "Control costs by routing tasks to faster, lower-cost models like Haiku". Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- "A subagent's context window is sized by its own model, not the parent's". Source: https://code.claude.com/docs/en/sub-agents, checked 2026-11-21.
- Claude Code gives a use for each effort level. `low`: "Quick exchanges where you review each result". `medium`: "day-to-day engineering work with a clear scope". `high`: "Work where verification matters or edge cases are likely". `max`: "may show diminishing returns and is prone to overthinking, so test before adopting it broadly". Source: https://code.claude.com/docs/en/model-config, checked 2026-11-21.
- Claude Code has a fixed role split with the name `opusplan`: it "uses `opus` during plan mode, then switches to `sonnet` for execution". Source: https://code.claude.com/docs/en/model-config, checked 2026-11-21.
- Claude Code handles new models with aliases: "Aliases point to the recommended version for your provider and update over time." It also says: "The effort scale is calibrated per model, so the same level name does not represent the same underlying value across models". Source: https://code.claude.com/docs/en/model-config, checked 2026-11-21.
- The default effort differs between the products for the same model. Claude Code says "Fable 5.2, Opus 5.5, Sonnet 5.5, and Haiku 5.5 default to `medium`". The API says `high` is the default "on every model that supports effort except Claude Opus 5.5 and Claude Haiku 5.5". Source: https://code.claude.com/docs/en/model-config and https://platform.claude.com/docs/en/build-with-claude/effort, checked 2026-11-21.

### Anthropic: engineering post on the multi-agent research system
- Anthropic's research system used "Claude Opus 4 as the lead agent and Claude Sonnet 4 subagents" and "outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval". The post has the date 2025-06-13. Source: https://www.anthropic.com/engineering/multi-agent-research-system, checked 2026-11-21.
- The post says that three factors "explained 95% of the performance variance in the BrowseComp evaluation": token usage (80% alone), the number of tool calls, and the model choice. Source: https://www.anthropic.com/engineering/multi-agent-research-system, checked 2026-11-21.
- The post gives evidence for the model before the budget: "upgrading to Claude Sonnet 4 is a larger performance gain than doubling the token budget on Claude Sonnet 3.7". Source: https://www.anthropic.com/engineering/multi-agent-research-system, checked 2026-11-21.
- The post scales effort by the count of agents and tool calls, not by a thinking level: "Simple fact-finding requires just 1 agent with 3-10 tool calls, direct comparisons might need 2-4 subagents with 10-15 calls each". These rules are in the lead agent's prompt. Source: https://www.anthropic.com/engineering/multi-agent-research-system, checked 2026-11-21.
- The post states the cost: "agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats". It says tasks with shared context or many dependencies between agents are "not a good fit for multi-agent systems today". Source: https://www.anthropic.com/engineering/multi-agent-research-system, checked 2026-11-21.
- The post has a separate citation agent that attributes claims to sources. The post does not state the model of that agent. Source: https://www.anthropic.com/engineering/multi-agent-research-system, checked 2026-11-21.

### OpenAI: Codex and API docs
- A Codex sub-agent inherits "the parent agent's model and reasoning effort" when neither is set. Codex resolves each setting from "an explicit spawn value, then the corresponding `[agents]` default, then the parent's value". A custom agent file's `model` or `model_reasoning_effort` takes precedence. Source: https://learn.chatgpt.com/docs/agent-configuration/subagents (redirect target of https://developers.openai.com/codex/subagents), checked 2026-11-21.
- The Codex config keys for the defaults are `agents.default_subagent_model` and `agents.default_subagent_reasoning_effort`. Source: https://learn.chatgpt.com/docs/agent-configuration/subagents, checked 2026-11-21.
- Codex has three built-in roles: `default`, `worker` ("execution-focused agent for implementation and fixes") and `explorer` ("read-heavy codebase exploration agent"). The page does not state a default model or effort for a role. Source: https://learn.chatgpt.com/docs/agent-configuration/subagents, checked 2026-11-21.
- The Codex sub-agent page gives a rule of thumb for each model and each effort. "`gpt-6.2-sol`: Use Sol for everyday agents that plan, use tools, and check their work." "`gpt-6-luna`: Use for fast, narrowly scoped agents handling clear, repeatable, or high-volume work." "`high`: Use when an agent needs to trace complex logic" (for example reviewer or security agents). "`low`: Use when the task is straightforward and speed matters most". Source: https://learn.chatgpt.com/docs/agent-configuration/subagents, checked 2026-11-21.
- The Codex sub-agent page states the cost: "subagent workflows consume more tokens than comparable single-agent runs". Source: https://learn.chatgpt.com/docs/agent-configuration/subagents, checked 2026-11-21.
- The Codex model page gives one line per model. The line for the smallest model contains a criterion that is not difficulty: "Choose Luna for specific, high-volume tasks when you know what a good result looks like". Source: https://learn.chatgpt.com/docs/models (redirect target of https://developers.openai.com/codex/models), checked 2026-11-21.
- The Codex model page makes the start effort depend on the model: start with the client's selection for GPT-6.2 Astra or Sol, with High for Luna, and with Light for GPT-6 Astra. It says: "Most tasks do not need Max or Ultra." Ultra "uses subagents to work on separate parts of a task in parallel". Source: https://learn.chatgpt.com/docs/models, checked 2026-11-21.
- The OpenAI reasoning guide gives a table of effort levels. `medium`: "Default configuration for most workloads, and a well-balanced point on the pareto curve of latency, performance and cost." `xhigh`: "Only use when your evals show a clear benefit that justifies the extra latency and cost". Source: https://developers.openai.com/api/docs/guides/reasoning, checked 2026-11-21.
- The OpenAI reasoning guide says: "Treat `reasoning.effort` as a tuning knob, not the primary way to recover quality." It also says that the levels and defaults "are also model-dependent rather than universal". Source: https://developers.openai.com/api/docs/guides/reasoning, checked 2026-11-21.

### Google: Gemini API, Gemini CLI and Antigravity CLI
- The Gemini thinking page gives a per-model table of thinking levels and defaults. The supported levels differ by model (for example `low, medium, high` for gemini-4-carbon and `low, medium, high, xhigh` for gemini-4-neon). Source: https://aistudio.google.com/docs/thinking (redirect target of https://ai.google.dev/gemini-api/docs/thinking), checked 2026-11-21.
- The Gemini thinking page maps task difficulty to the level: "Simple tasks: Use minimal thinking for fact retrieval or classification", "Moderate tasks: Use default thinking for comparing concepts or creative reasoning", "Complex tasks: Use maximum thinking for advanced coding, math, or multi-step planning". Source: https://aistudio.google.com/docs/thinking, checked 2026-11-21.
- The Gemini thinking page gives a selection procedure: "Run your evaluations at all four levels" and then "pick the lowest `thinking_level` that meets your quality bar". Source: https://aistudio.google.com/docs/thinking, checked 2026-11-21.
- Gemini CLI's default model is `auto`. Its precedence is the `--model` flag, the `GEMINI_MODEL` environment variable, `model.name` in `settings.json`, the local Gemma router if enabled, then `auto`. The routing page does not state the criteria that `auto` uses. Source: https://geminicli.com/docs/cli/model-routing/, checked 2026-11-21.
- Gemini CLI has an experimental option in which "a locally-running Gemma model" makes the routing decision in place of a hosted model. Source: https://geminicli.com/docs/cli/model-routing/, checked 2026-11-21.
- A Gemini CLI sub-agent definition has a `model` field that "Defaults to `inherit`". The schema lists `temperature`, `max_turns` and `timeout_mins`, and no thinking field. The page gives no guidance on the model choice. Source: https://geminicli.com/docs/core/subagents/, checked 2026-11-21.
- Google moved individual users from Gemini CLI to Antigravity CLI. On 2026-06-18 Gemini CLI stopped serving requests for Google AI Pro and Ultra subscribers and free individual users. It stays available with paid API keys and for enterprise customers. Subagents carry over to Antigravity CLI. Source: https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/, checked 2026-11-21.
- Antigravity's model page says its default "Orchestrator" option "isn't a router that classifies your prompt upfront". It recommends Orchestrator for "Most day-to-day development" and a single Gemini 4 model for "Work where every intermediate step needs maximum reasoning depth on a single model". Source: https://antigravity.google/docs/models.md, checked 2026-11-21.
- Antigravity CLI has `/effort` and `--effort` with the levels `low`, `medium`, `high`, `xhigh`, `max`, by model. It gives one line per level, for example `low`: "well suited for quick lookups, syntax checks, and straightforward edits" and `high`: "deeper reasoning for complex architecture, subtle bug investigations, and multi-file refactoring". The page says nothing on sub-agents. Source: https://antigravity.google/docs/cli/commands/effort/, checked 2026-11-21.

### Routers and routing research
- RouteLLM is an open-source framework "for serving and evaluating LLM routers". It routes each query between one strong model and one weak model with a cost threshold. Its routers (`mf`, `sw_ranking`, `bert`, `causal_llm`) are trained on preference data from Chatbot Arena. Source: https://github.com/lm-sys/RouteLLM, checked 2026-11-21.
- RouteLLM reports cost reductions "by up to 85%" while it keeps "95% GPT-4 performance" on MT Bench. The benchmarks (MT Bench, MMLU, GSM8K) are single-turn question sets, not agent tasks. Source: https://github.com/lm-sys/RouteLLM, checked 2026-11-21.
- RouteLLM's routers were trained on the pair GPT-4 and Mixtral. The README says they "generalize well to other strong and weak model pairs". It says the threshold must be calibrated on the user's own queries. The repository shows no release and 5.7k stars. Source: https://github.com/lm-sys/RouteLLM, checked 2026-11-21.
- OpenRouter's Auto Router (`openrouter/auto`) "picks a model and a reasoning effort for each request". It is the one source in this survey that selects the effort level automatically. Source: https://openrouter.ai/docs/guides/routing/routers/auto-router, checked 2026-11-21.
- The Auto Router's stated method: "A fast decision model rates eleven aspects of the request in one call", such as task type and difficulty. The policy "weighs that rating against live prices, cache status, and benchmark performance" inside a `cost_tier` of `low`, `medium` or `high`. Source: https://openrouter.ai/docs/guides/routing/routers/auto-router, checked 2026-11-21.
- The Auto Router has no added fee. The user limits the pool with `allowed_models` and `excluded_models`. Source: https://openrouter.ai/docs/guides/routing/routers/auto-router, checked 2026-11-21.
- OpenRouter publishes a router benchmark page with 182 router and baseline runs on five benchmarks (Deep SWE, SWE Atlas QA, Terminal Bench 4.0, Tau3 Banking, MMMU Pro Vision). The last run on the page has the date 2026-11-21. The publisher of the page is also the vendor of three of the routers. Source: https://openrouter.ai/benchmarks/routers, checked 2026-11-21.
- On that page the results are mixed by benchmark. On SWE Atlas QA the router "Auto Code" scored 62.5% at $0.66 per task against 55.6% at $0.79 for Claude Opus 5.5 (high). On Terminal Bench 4.0 Claude Opus 5.5 scored 53.1% at $22.60 against 50.0% at $4.96 for Auto Code. Source: https://openrouter.ai/benchmarks/routers, checked 2026-11-21.
- LLMRouterBench (arXiv, 2026-01-12) re-evaluated 10 routing baselines on "over 400K instances from 21 datasets and 33 models". It found that "several recent approaches, including commercial routers, fail to reliably outperform a simple baseline" and that "a substantial gap remains to the Oracle, driven primarily by persistent model-recall failures". Source: https://arxiv.org/abs/2601.07206, checked 2026-11-21.

### Measurements of effort against quality and cost
- A preprint with the title "What Effort Level Should I Choose? On the Economics of Reasoning Effort in LLM Agents" (arXiv, 2026-10-25) tested proprietary and open-weight models on four benchmarks, "spanning single-call reasoning and long-horizon agentic tasks". Source: https://arxiv.org/abs/2610.34491, checked 2026-11-21.
- The preprint reports that higher effort "frequently fails on tasks that lower effort solved", and that on easy tasks that every level solves, the highest level costs "up to 42x as much as the lowest". Source: https://arxiv.org/abs/2610.34491, checked 2026-11-21.
- The preprint's recommendation is a procedure: start at the lowest effort and escalate only after a verified failure. The authors report that this "matches or improves on fixed top effort across all models and benchmarks at lower cost for most proprietary models". Source: https://arxiv.org/abs/2610.34491, checked 2026-11-21.
- Vals AI (article date 2026-11-03) ran seven models at three effort settings on about half the tasks of its eight index benchmarks. Its summary: "Lowering reasoning effort reduces cost much more than it reduces score." At the lowest setting Claude Opus 5.5 kept 80% of its score at 16% of the cost. Source: https://www.vals.ai/blogs/reasoning-effort, checked 2026-11-21.
- Vals AI reports that the gain from effort depends on the task type. Legal Research gained a median of 19.2 points from more reasoning; three other benchmarks gained under 6 points each. In 22 of 56 model-benchmark pairs a lower setting scored as high at lower cost. Source: https://www.vals.ai/blogs/reasoning-effort, checked 2026-11-21.
- Vals AI states its limits: about half the tasks, one run per setting for most benchmarks, and "No significant difference does not mean the scores are equal". Source: https://www.vals.ai/blogs/reasoning-effort, checked 2026-11-21.

### Other coding agents
- Claude Code's advisor tool pairs a main model with a stronger advisor that Claude consults "before committing to an approach, when stuck on a recurring error, or before declaring a task complete". The setting is `advisorModel`, `/advisor` or `--advisor`. The tool is experimental. Source: https://code.claude.com/docs/en/advisor, checked 2026-11-21.
- The advisor page gives a table of pairings with a use for each, for example "Opus main + Opus advisor: A second Opus reviews the first. Useful for high-stakes tasks where an independent check matters more than cost". Sub-agents inherit the configured advisor. Source: https://code.claude.com/docs/en/advisor, checked 2026-11-21.
- In Amp, the Task and Read Thread sub-agents "run the same model and reasoning effort as the thread that started them". The Oracle, Librarian and Finder sub-agents are plugins; the user sets `MODEL` and `REASONING_EFFORT` in the plugin file. Source: https://ampcode.com/docs/models-and-subagents, checked 2026-11-21.
- Amp's stated reason for a role split: "This routing lets Amp use a frontier model where deep reasoning matters and a faster specialist where speed matters more." The page names no model for a role. Source: https://ampcode.com/docs/models-and-subagents, checked 2026-11-21.
- A Cursor sub-agent definition has a `model` field with `inherit` (the default) or a model ID. The effort level is a bracket option on the model ID, for example `claude-opus-5[effort=high]`. Source: https://cursor.com/docs/subagents, checked 2026-11-21.
- Cursor's one criterion for the sub-agent model: "Choose `inherit` when the subagent needs the same reasoning power as the parent." Its built-in Explore sub-agent "uses a faster model to run many parallel searches". Source: https://cursor.com/docs/subagents, checked 2026-11-21.
- Cursor states the cost: "Running five subagents in parallel uses roughly five times the tokens of a single agent". Source: https://cursor.com/docs/subagents, checked 2026-11-21.
- GitHub Copilot's auto model selection combines two systems: "One system tracks real-time system health and availability, while the other evaluates task complexity." The user picks a tier: Efficiency, Balance or Intelligence. The page does not say that it selects an effort level, and it does not mention sub-agents. Source: https://docs.github.com/en/copilot/concepts/models/auto-model-selection, checked 2026-11-21.
- Copilot limits when the router can change the model: "Routing occurs along natural cache boundaries and large drifts in conversation complexity". Source: https://docs.github.com/en/copilot/concepts/models/auto-model-selection, checked 2026-11-21.
- Fireworks' FireRouter "routes at the task level across both open and closed models" and is "cache aware". Fireworks reports $7.42 per session with FireRouter against $15.81 for Opus 5 alone over 2,334 production sessions. The post has the date 2026-09-21 and comes from the vendor. Source: https://fireworks.ai/blog/llm-model-routing-deepswe, checked 2026-11-21.
- The same Fireworks post states the central limit of a router: "a router has to choose before it sees the outcome". Its 97.6% figure is a hindsight oracle over 18 models, which the post says "biases it upward". It also says "a stable error distribution beats a router that unpredictably picks the wrong specialist". Source: https://fireworks.ai/blog/llm-model-routing-deepswe, checked 2026-11-21.
- Hyper's setup page for Claude Code sets `CLAUDE_CODE_SUBAGENT_MODEL` to `deepseek-v4-flash`, a cheaper model than the main model `deepseek-v4-pro`, for all sub-agent work. The page does not mention Prism or an effort level. Source: https://hyper.charm.land/docs/coding-agents/claude-code.html, checked 2026-11-21.
- The Crush release v0.65.2 (date shown as "01 May", year not shown) added support for "Hyper, our inference service for coding focused on price, performance, and privacy" and said: "Hyper's currently in private beta". Source: https://github.com/charmbracelet/crush/releases/tag/v0.65.2, checked 2026-11-21.
- An Antigravity sub-agent definition has a `model` field: "Model tier used when invoked (`inherit`, `flash`, or `pro`)". The default is `inherit`. The page lists no field for an effort or thinking level and gives no guidance on the tier. Source: https://antigravity.google/docs/subagents, checked 2026-11-21.

### Older guidance and one more measurement
- Anthropic's post "Building effective agents" (2024-12-19) describes routing as a workflow: "Routing easy/common questions to smaller, cost-efficient models like Claude Haiku 4.5 and hard/unusual questions to more capable models like Claude Sonnet 4.5". The page shows newer model names than its date, so Anthropic updates the names in place. Source: https://www.anthropic.com/engineering/building-effective-agents, checked 2026-11-21.
- A preprint (arXiv, 2026-07-02, one author, 90 agent runs that build one application) reports that a rise from High to xHigh "lifted first try perfect runs from 28 percent to 89 percent" for 9 to 29 percent more cost. Source: https://arxiv.org/abs/2607.02436, checked 2026-11-21.
