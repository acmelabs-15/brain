# RES-111: Survey: mechanisms that can stop or redirect an agent

## Question
Survey, area 1 of 3: which mechanisms can stop or redirect an agent on each host, and what can each one see and do, for the seven survey questions?

## Answer
This is a map of 34 mechanisms on five hosts and outside them. It is not a design recommendation. Every cell comes from the docs or local files in Findings. No mechanism was run.

Each of the five hosts has a hook before a tool call that can deny the call with a reason for the agent. Each has a hook at the end of a turn that can make the agent continue. Each passes a transcript path to hooks. The hosts differ on three points: whether a hook can make the host ask the user, whether a model can judge inside a hook, and whether a loop cap exists.

### Moments against mechanisms: can it see the moment

"See" means: the mechanism runs at that moment and gets data that shows it. It does not mean that the mechanism can judge the moment. That is area 2.

### Where the sources agree

- A pre-tool hook with a deny and a reason for the agent exists on all five hosts.
- An end-of-turn hook that forces one more turn exists on all five hosts.
- The default on failure is that the action goes ahead. Claude Code, Gemini CLI, Antigravity and Cursor state this. Claude Code and Cursor have an opt-in to block on failure.
- The pages read state no latency number for a hook. The only number found is the example plugin's own claim for its model call, 70 to 500 ms.

### Where the sources disagree or differ

- A hook that makes the host ask the user: Claude Code and Antigravity support it. Codex parses `ask` and does not support it. The Gemini CLI hook reference lists no such decision. Cursor enforces `ask` for shell and MCP hooks and not for `preToolUse`.
- A model that judges inside a hook: Claude Code has prompt and agent hooks. Cursor has prompt hooks, but not in plugins. Codex skips them. Gemini CLI has only command hooks. The two Antigravity pages disagree.
- Loop caps: Claude Code states 8, Cursor states 5. Codex, Gemini CLI and Antigravity state none.
- Delivery: a Claude Code plugin hook runs when the plugin is enabled. A Codex plugin hook waits for the user's review of each hook.
- Three public issue reports say that `ask` did not prompt in some Claude Code setups. The docs say `deny` holds in every permission mode.
- The installed `plugin-dev:hook-development` skill is behind the docs on prompt hook events and input field names.

### Topics worth a deep run

1. What a Claude Code prompt hook and agent hook receive and return on `Stop` and `PreToolUse`. The docs do not state if a prompt hook gets the conversation. `Stop` is the one settings hook that sees moment 3.
2. The mod path on Claude Code: `tool.call` with `$.ui.ask`, `$.session.messages()` and `$.model.fork`. It is the one mechanism that asks the user itself and reads the conversation in process. The guard, the version floor and `-p` runs limit it, and none of this was run.
3. `PreToolUse` on writes to record files, on all five hosts. It covers moments 1 and 2 everywhere. Open points are the agent's next action after a deny, the reliability of `ask`, and the lag of the transcript file.
4. The sub-agent return path on Claude Code: `PostToolUse` on `Agent`, `SubagentHandback`, and `UserPromptSubmit` for a background report. The three paths give different data, and moment 2 depends on which one a session uses.
5. Parity on the other hosts: no `ask` and a trust review on Codex, no stated loop cap on three hosts, `force_ask` and `lastUserInput` on Antigravity. A design that needs "ask the user" has no equal on Codex and Gemini CLI hooks today.

### RES-035 findings checked against today's docs

Still hold:

- `SessionStart` takes only `command` and `mcp_tool` handlers. Prompt and agent hooks do not run on it.
- `additionalContext` arrives as a system reminder, with a 10,000-character cap and the advice to write factual statements.
- `UserPromptSubmit` fires on each prompt and on scheduled tasks, background subagent reports and cross-session messages. It adds context or blocks, cannot replace the prompt, and has a 30-second default.
- `PreToolUse` `deny` prevents the call, the reason reaches Claude, and the hook fires only on a tool call.
- `Stop` with `block` or context continues the turn, with `stop_hook_active` and a cap of 8. Today's docs add that the count resets on a tool call.
- `asyncRewake` wakes Claude on exit code 2, and a `-p` run kills async hooks.
- Skill frontmatter hooks register only after the skill is invoked. Plugin agents ignore `hooks`, `mcpServers` and `permissionMode`.
- Mods: on by default from v2.1.287, the list of places they run, the settings that stop them, the guard that passes over prompt events, `prompt.submit` rewrite and context, `$.prompt.submit` to start a turn.
- Codex: the hook events, the 2,500-token limit, `Stop` block as a continuation prompt, `PreToolUse` deny, the trust review by hash, and `--dangerously-bypass-hook-trust`.
- Gemini CLI: extension hooks in `hooks/hooks.json`, `BeforeAgent` context, `BeforeModel` override and synthetic response, `AfterAgent` deny as a retry, no loop cap in the docs.
- Antigravity: the six events in a plugin root `hooks.json`, `PreToolUse` deny, `PostInvocation` `force_continue`, fail open on a non-zero exit.

Changed or not confirmed:

- RES-035 says Antigravity `Stop` returns `block`. Today's pages give `decision: "continue"`.

## Findings
- Terms: "moment 1" is a user pushback that the agent answers with a file write. "Moment 2" is a delegated agent's result that the agent records as final. "Moment 3" is a conflict between the user's direction and a skill instruction that the agent settles in silence. Source: the survey brief for IDEA-018#02, checked 2026-11-21.
- Claude Code hooks have five handler types: `command`, `http`, `mcp_tool`, `prompt` and `agent`. Agent hooks are marked experimental. Source: https://code.claude.com/docs/en/hooks.md#hook-handler-fields, checked 2026-11-21.
- Claude Code lists 33 hook events. The ones that can block are `PreToolUse`, `UserPromptSubmit`, `UserPromptExpansion`, `Stop`, `SubagentStop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`, `ConfigChange`, `PostToolBatch`, `PreCompact`, `PreModelSwitch`, `Elicitation`, `ElicitationResult`, `WorktreeCreate` and `WorktreeRemove`. Source: https://code.claude.com/docs/en/hooks.md#exit-code-2-behavior-per-event, checked 2026-11-21.
- Hook events have three cadences: per session (`SessionStart`, `SessionEnd`), per turn (`UserPromptSubmit`, `Stop`, `StopFailure`) and per tool call (`PreToolUse`, `PostToolUse`). `EndConversation` calls skip the tool events. Source: https://code.claude.com/docs/en/hooks.md#hook-lifecycle, checked 2026-11-21.
- Every hook gets `session_id`, `transcript_path`, `cwd` and `hook_event_name`, and most get `permission_mode`. The transcript file is written asynchronously and can lag the current turn. Source: https://code.claude.com/docs/en/hooks.md#common-input-fields, checked 2026-11-21.
- A hook inside a subagent gets `agent_id` and `agent_type`. Hooks from settings files, managed settings and plugins also run inside subagents. Source: https://code.claude.com/docs/en/hooks.md#hook-locations, https://code.claude.com/docs/en/hooks.md#common-input-fields, checked 2026-11-21.
- `PreToolUse` gets `tool_name`, `tool_input` and `tool_use_id`. It returns `permissionDecision` `allow`, `deny`, `ask` or `defer`, plus `updatedInput` and `additionalContext`. With several hooks the order is `deny` > `defer` > `ask` > `allow`. Source: https://code.claude.com/docs/en/hooks.md#pretooluse-decision-control, checked 2026-11-21.
- After a `PreToolUse` `deny`, Claude sees `permissionDecisionReason` as the reason. For `ask`, the user sees the reason in the permission prompt, with a label such as `[plugin:<name>]`. In a `-p` run where no one can answer, Claude Code denies the call and Claude reads the reason in the tool result. Source: https://code.claude.com/docs/en/hooks.md#pretooluse-decision-control, checked 2026-11-21.
- `PreToolUse` runs only when Claude calls a tool. A file that the user references with `@` enters the prompt with no tool call and no hook. Source: https://code.claude.com/docs/en/hooks.md#pretooluse, checked 2026-11-21.
- `defer` ends the turn with `stop_reason: "tool_deferred"` so that a calling process can collect input and resume. It works only with `-p` and only when the turn holds one tool call. An interactive session ignores it with a warning. Source: https://code.claude.com/docs/en/hooks.md#defer-a-tool-call-for-later, checked 2026-11-21.
- A `PreToolUse` hook can answer `AskUserQuestion` itself: it returns `allow` with `updatedInput` that holds an `answers` object. `allow` alone is not sufficient for that tool. Source: https://code.claude.com/docs/en/hooks.md#tools-that-require-user-interaction, checked 2026-11-21.
- `PermissionRequest` runs only when Claude Code is about to show a permission prompt. It returns `decision.behavior` `allow` or `deny`, with `message` and `interrupt` for a deny. Exit code 2 has no effect on it. Source: https://code.claude.com/docs/en/hooks.md#permissionrequest-decision-control, checked 2026-11-21.
- `PostToolUse` gets `tool_input` and `tool_response`. `decision: "block"` adds the `reason` next to the tool result, but the tool already ran. It can also return `additionalContext` and `updatedToolOutput`. Source: https://code.claude.com/docs/en/hooks.md#posttooluse-decision-control, checked 2026-11-21.
- `PostToolBatch` runs once after a batch of parallel tool calls and before the next model call. It gets `tool_calls` with each `tool_response` as the model sees it. `decision: "block"` or `continue: false` stops the agentic loop, and the message stays in the conversation. Source: https://code.claude.com/docs/en/hooks.md#posttoolbatch, checked 2026-11-21.
- `UserPromptSubmit` gets the `prompt` text. It can block the prompt or add `additionalContext`, and it cannot replace the prompt. On a block, the `reason` goes to the user and is not added to context. Source: https://code.claude.com/docs/en/hooks.md#userpromptsubmit-decision-control, checked 2026-11-21.
- `UserPromptSubmit` also fires when a background subagent reports back to the session, when a scheduled task fires, and when another session sends a message. Source: https://code.claude.com/docs/en/hooks.md#userpromptsubmit, checked 2026-11-21.
- `Stop` runs when the main agent finishes its reply, and not after a user interrupt. It gets `stop_hook_active`, `last_assistant_message`, `background_tasks` and `session_crons`. `decision: "block"` with a `reason`, or `additionalContext`, makes the turn continue. Source: https://code.claude.com/docs/en/hooks.md#stop, checked 2026-11-21.
- Claude Code ends the turn after 8 consecutive `Stop` continuations. The count resets each time Claude calls a tool, and `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` raises the cap. Source: https://code.claude.com/docs/en/hooks.md#stop-input, checked 2026-11-21.
- `SubagentStop` gets `agent_type`, `agent_transcript_path` and `last_assistant_message`, the subagent's final text. A block keeps the subagent running. To add context to the parent session after a subagent returns, the docs name a `PostToolUse` hook on the `Agent` tool. Source: https://code.claude.com/docs/en/hooks.md#subagentstop, checked 2026-11-21.
- A `PostToolUse` hook on `Agent` gets the foreground subagent's result in `tool_response.content`. A background subagent returns `status: "async_launched"` with no result. Source: https://code.claude.com/docs/en/hooks.md#pretooluse-input (section "Agent"), checked 2026-11-21.
- From v2.1.271, a subagent in auto mode delivers its report through the `SubagentHandback` tool. A `PreToolUse` or `PostToolUse` hook on that tool reads the report as `tool_input.message`. A `deny` makes Claude Code ask the subagent up to three times to send the report again. Source: https://code.claude.com/docs/en/hooks.md#pretooluse-ask-decisions-in-auto-mode, https://code.claude.com/docs/en/hooks.md#subagentstop-input, checked 2026-11-21.
- `TaskCreated` and `TaskCompleted` can block a task's creation or completion and return a message to Claude. `TeammateIdle` can keep an agent team teammate working. Source: https://code.claude.com/docs/en/hooks.md#taskcompleted-decision-control, https://code.claude.com/docs/en/hooks.md#teammateidle-decision-control, checked 2026-11-21.

- Gemini `AfterAgent` gets `prompt`, `prompt_response` and `stop_hook_active`. `decision: "deny"` rejects the response and sends the `reason` to the agent as a new prompt. A loop cap is not stated. Source: https://geminicli.com/docs/hooks/reference.md#afteragent, checked 2026-11-21.
- Gemini `BeforeModel` gets `llm_request` with the `messages` of the request. It can override the request, return a synthetic response in place of the model call, or deny the turn. `AfterModel` fires for every response chunk. Source: https://geminicli.com/docs/hooks/reference.md#beforemodel, checked 2026-11-21.
- In Gemini CLI, exit code 2 blocks the action. Any other non-zero exit code is a warning and the action proceeds. Non-JSON text on stdout makes the CLI default to "Allow". Source: https://geminicli.com/docs/hooks.md#exit-codes, checked 2026-11-21.
- A Gemini extension ships hooks in `hooks/hooks.json`. Project hooks are fingerprinted, and a changed hook counts as new and untrusted. The user can disable one hook with `/hooks disable <name>` or all with `/hooks disable-all`. Source: https://geminicli.com/docs/extensions/reference.md#hooks, https://geminicli.com/docs/hooks.md#security-and-risks, checked 2026-11-21.
- The Gemini CLI policy engine gives a tool call the decision `allow`, `deny` or `ask_user`. In non-interactive mode `ask_user` acts as `deny`. An extension can ship rules in `policies/*.toml`, and its `allow` decisions are ignored. User and admin rules have a higher priority. Source: https://geminicli.com/docs/reference/policy-engine.md#decisions, https://geminicli.com/docs/extensions/reference.md#policy-engine, checked 2026-11-21.
- Antigravity lists 6 hook events: `SessionStart`, `PreToolUse`, `PostToolUse`, `PreInvocation`, `PostInvocation` and `Stop`. The handler type is `command`, with a default timeout of 30 seconds. Source: https://antigravity.google/docs/hooks, checked 2026-11-21.
- Every Antigravity hook gets `conversationId`, `workspacePaths`, `transcriptPath`, `artifactDirectoryPath`, `modelName` and `lastUserInput`, the most recent user prompt. Source: https://antigravity.google/docs/hooks (section "Common input fields"), checked 2026-11-21.
- Antigravity `PreToolUse` gets `toolCall.name` and `toolCall.args`. Its `decision` is `allow`, `auto_approve`, `deny`, `ask`, `force_ask` or `deny_unless_prior_grant`, with a `reason` shown to the agent or the user. `force_ask` always prompts and ignores cached permissions. `overwrite` changes the arguments. Source: https://antigravity.google/docs/hooks (section "PreToolUse"), checked 2026-11-21.
- Antigravity `PostToolUse` gets the tool call and an error text, and not the tool output. It returns an empty object. Source: https://antigravity.google/docs/hooks (section "PostToolUse"), https://antigravity.google/docs/build-plugins (section "Lifecycle hooks"), checked 2026-11-21.
- Antigravity `PreInvocation` fires before each model call. It can inject steps, such as a system message or a user message, and `terminationBehavior: "terminate"` stops before the model call. `PostInvocation` can return `force_continue` or `terminate`. Source: https://antigravity.google/docs/hooks (sections "PreInvocation" and "PostInvocation"), checked 2026-11-21.
- Antigravity `Stop` gets `terminationReason` and `fullyIdle`. `decision: "continue"` re-enters the loop and injects the `reason` as a system message. A loop cap is not stated. Source: https://antigravity.google/docs/hooks (section "Stop"), checked 2026-11-21.
- An Antigravity plugin ships hooks in a root `hooks.json`. Any non-zero exit code is logged and ignored, so the hook fails open. A hook group has an `enabled` field, and `/hooks` lists the loaded hooks. Source: https://antigravity.google/docs/build-plugins (section "Lifecycle hooks"), https://antigravity.google/docs/hooks, checked 2026-11-21.
- The two Antigravity pages disagree on handler types. The plugin page says hooks are "shell commands or prompt evaluations". The hooks page says only `command` is supported. Source: https://antigravity.google/docs/build-plugins (table "Lifecycle hooks"), https://antigravity.google/docs/hooks (section "Hook handler configuration"), checked 2026-11-21.
- Antigravity CLI permissions are `deny`, `ask` and `allow` lists of `action(target)` entries in the user's settings, in the order Deny > Ask > Allow. The tool list names an `ask_question` tool for multiple-choice questions. Source: https://antigravity.google/docs/permissions (section "CLI fine-grained permissions"), https://antigravity.google/docs/hooks (section "Interaction and media"), checked 2026-11-21.
- Cursor lists agent hooks that include `preToolUse`, `postToolUse`, `subagentStart`, `subagentStop`, `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `afterFileEdit`, `beforeSubmitPrompt`, `afterAgentResponse`, `afterAgentThought` and `stop`. Hook types are `command` and `prompt`. Source: https://cursor.com/docs/hooks.md#hook-categories, https://cursor.com/docs/hooks.md#hook-types, checked 2026-11-21.
