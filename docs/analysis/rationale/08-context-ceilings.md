# 08 · Long-context ceilings per model

**Status:** the source of `docs/plan/context-ceilings.json`. Three values per model: **`ceiling`** (the strict knee below — where 8-needle recall across the *whole* context first degrades with statistical confidence), **`plateau`** (where degradation stops being graceful), and — added 2026-09-05 — **`governing`**, the operating ceiling `budget.ts` actually uses. `governing` is set only from this project's own evidence: a conversation that peaked at or above the value with zero rot metrics. Today only Gemini 3.8 Flash has one (25%: zero rot metrics through an 18.08% peak, and the plateau as the bound); every other model is governed by its strict knee until a conversation on it produces evidence; the file's `raise_rule` says how a value grows.

**Why strict knee and governing differ.** MRCR measures retrieval of eight needles scattered through a context the model must hold entirely in attention. The primary agent's work is different in kind: it re-reads files from disk on demand and every fact it records is checked by a script against the source. Zero rot metrics through 18% on the real workload is direct evidence; the benchmark is the bound we refuse to cross without such evidence.

# Long-context ceilings for Antigravity / Claude Code models (as of 2026-09-04)

## Method note (how the "ceiling" was derived)

Primary evidence is **GDM-MRCR v2, 8-needle** — the only long-context eval with per-context-bin scores for these models. Two independent sources report it and they **agree within ~2 points** wherever they overlap (Google's "128k cumulative" vs Context Arena `cum_avg_128k`: 3.7 Flash 97.0 vs 96.0; 3.1 Pro 84.9 vs 85.1; Sonnet 4.6 84.9 vs 83.1; Opus 4.6 84.0 vs 82.2), so I treat the Context Arena per-bin curves as reliable. [EVAL] Context Arena bins are `(lo, hi]` token ranges, ~80–310 samples per bin, graded with `difflib.SequenceMatcher.ratio()`; 8-needle is labelled "Hard" and "the most meaningful discriminator" (https://contextarena.ai/ site FAQ; data from https://contextarena.ai/api/leaderboard?needles=8&mode=full and `https://contextarena.ai/api/models/<slug>/summary`). Only 8-needle data exists on the site today (`/api/available-needles` → `{"needles":[8]}`); 2- and 4-needle queries return empty.

Two thresholds per model:
- **Onset bin** = first bin whose point estimate is >5 pts below the short-context level (best of the ≤8k/≤16k bins) — what you asked for.
- **Knee** = first bin where the 95% CI upper bound is also below (base − 5), i.e. degradation is statistically confirmed. **Recommended ceiling = lower edge of the knee bin ÷ window**; the strict onset alternative is given in the note. This is a rule I chose, stated so you can swap it.

All MRCR numbers below are Context Arena unless marked otherwise; reasoning level in brackets.

Cross-cutting evidence for where degradation begins in general:
- Anthropic docs: "As token count grows, accuracy and recall degrade, a phenomenon known as context rot" — no threshold given [DOC] https://platform.claude.com/docs/en/build-with-claude/context-windows; same in the engineering post ("attention budget", n² pairwise relationships) [DOC] https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents.
- Claude Code's own default is to compact **at the model limit** (Sonnet 5 at ~967K), i.e. Anthropic's tooling imposes no lower ceiling [DOC] https://code.claude.com/docs/en/model-config.
- Google's long-context doc: "up to 99% accuracy" for single-needle, but "multiple 'needles'… the model does not perform with the same accuracy. Performance can vary to a wide degree" [DOC] https://ai.google.dev/gemini-api/docs/long-context.
- Chroma "Context Rot" (18 models, 2025): "performance grows increasingly unreliable as input length grows"; degradation is monotonic and steeper for low-similarity needles and with distractors; no explicit safe fraction [EVAL] https://www.trychroma.com/research/context-rot.
- NoLiMa: "At 32K… 11 models drop below 50% of their strong short-length baselines"; effective length (≥85% of base) ≤16K for every model tested, e.g. GPT-4.1 (1M claimed) 16K, Gemini 2.5 Flash (1M) 2K, Claude 3.5 Sonnet (200K) 4K [EVAL] https://arxiv.org/abs/2502.05167 and https://github.com/adobe-research/NoLiMa. Older-generation models only.
- RULER: "only half of them can maintain satisfactory performance at the length of 32K" (17 models, 2024) [EVAL] https://arxiv.org/abs/2404.06654, https://github.com/NVIDIA/RULER.
- LongBench v2: 8k–2M words, best model 57.7% vs human 53.7%; no per-length breakdown extracted [EVAL] https://arxiv.org/abs/2412.15204.
- Fiction.LiveBench (comprehension, last updated 2026-04-04): Gemini 3 Pro preview 100 → 96.9 at 192k; Gemini 3 Flash preview 100 at 192k; GPT-5.2 96.9 at 192k — comprehension on these models holds far longer than 8-needle recall does [EVAL] https://fiction.live/stories/Fiction-liveBench-April-04-2026/oQdzQvKHw8JyXbN87.
- Practitioner: HumanLayer "keeping utilization in the 40%-60% range (depends on complexity of the problem)" [COMMUNITY] https://www.humanlayer.dev/blog/advanced-context-engineering; Sikkema recommends autocompact at 70% of 200K (~140k) and cites Aider's Gauthier "~25-30k tokens" confusion onset [COMMUNITY] https://www.albertsikkema.com/ai/development/tools/2026/04/23/smaller-context-window-better-claude-code.html; a Claude Code issue reports "0–20% reliable, 20–40% degrading, 40–60% unreliable" on the 1M window (anecdotal, closed as not planned) [COMMUNITY] https://github.com/anthropics/claude-code/issues/35296; yage.ai claims "effective context capacity is typically only 60–70% of nominal" without a cited method [COMMUNITY] https://yage.ai/share/long-context-benchmark-en-20260315.html.

## (B) Fallback rule

**`budget = min(0.30 × window, 65,536)`** — i.e. `default.ceiling = 0.30`, `default.maxTokens = 65536`.

Why: for the six frontier models with per-bin data, the CI-confirmed knee is an **absolute** token count between 32k and 128k (32k, 32k, 32k, 64k, 64k, 128k; median 64k) even though every one of them has a 1M nominal window [EVAL, Context Arena]. So the fallback should be an absolute cap, not a fraction — a fraction of 1M would be wrong by an order of magnitude. 64k is the median knee and is also the largest bin at which every model here still scores ≥68%. The 0.30 fraction only matters for small windows (a 128K model → 38k; a 32K model → 10k) and is grounded in older-generation evidence that unknown/weaker models have effective lengths of 2–16k and fail at 32k (NoLiMa, RULER); it sits below the community 40–60% heuristic on purpose because that heuristic predates the per-bin data. Use it for any model without an entry, and for Gemini 3.8 Flash if you reject the 3.7-proxy.
