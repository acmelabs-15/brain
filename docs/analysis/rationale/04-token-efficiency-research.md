## 1. Addy Osmani's `agent-skills` SDD cache hooks

**What it is [DOC — read from source]**
- Two Claude Code hooks (`PreToolUse` + `PostToolUse`, both matched on `WebFetch`) that implement a cross-session **HTTP resource cache for `WebFetch` results**, not a prompt/KV cache. https://github.com/addyosmani/agent-skills/blob/main/hooks/SDD-CACHE.md
- **Key**: `sha256(URL)` truncated to 32 hex chars; file at `${CLAUDE_PROJECT_DIR:-$PWD}/.claude/sdd-cache/<key>.json`. Prompt is stored as metadata only, not part of the key. https://raw.githubusercontent.com/addyosmani/agent-skills/main/hooks/sdd-cache-pre.sh
- **Stored**: `{url, prompt, etag, last_modified, content, fetched_at}`. `content` is the model-post-processed WebFetch result (`.tool_response.result`), not raw HTML. https://raw.githubusercontent.com/addyosmani/agent-skills/main/hooks/sdd-cache-post.sh
- **Invalidation**: no TTL. Pre-hook sends `curl -sI` with `If-None-Match`/`If-Modified-Since`; only a **304** serves from cache. Entries without ETag/Last-Modified are never cached (post-hook `rm -f`s any stale entry). Post-hook does an extra HEAD to capture validators from the *final* redirect hop.
- **Mechanism**: on hit, pre-hook writes the cached body to **stderr and exits 2**, which in Claude Code blocks the tool call and shows stderr to the model as the "result". This matches the hooks reference: "Exit 2 means a blocking error… stderr is shown to Claude as the reason for the block." https://code.claude.com/docs/en/hooks
- **Harness**: Claude Code only (reads `tool_input.url`, `CLAUDE_PROJECT_DIR`, `.claude/settings.json`). Dependencies: `jq`, `curl`, `shasum`/`sha256sum`, bash 3.2+.
- **Author's own caveats**: cached content reflects the first agent's prompt; per-project local only; no defense against wrong 304s; "treat as diagnostic data, not a caching guarantee".

**→ us**
- *Does not apply directly*: it caches web fetches; your cost is re-reading local files and re-sending stable prefixes.
- *Reusable pattern*: (1) the **PreToolUse-block-with-exit-2 substitution trick** — a hook can short-circuit any tool call and hand the model a precomputed result; (2) **key by content hash + validator, not TTL**; (3) **store the deliverable, not the input**. This is the mechanical basis for idea 5(c) — memoizing subagent runs keyed on input hashes (see §5c).
- Note the design decision worth copying: they key on the URL but *surface* the original prompt so a later agent can judge relevance. For us: key on `(hash(inputs), hash(METHOD.md), hash(prompt template))` and surface the METHOD version in the cached deliverable header.

## 2. Anthropic / Claude Code

### 2.1 API prompt-caching mechanics [DOC] — https://platform.claude.com/docs/en/build-with-claude/prompt-caching
- `cache_control: {"type":"ephemeral"}` = 5-minute TTL; `{"type":"ephemeral","ttl":"1h"}` = 1-hour. Max **4 breakpoints** per request (automatic top-level caching consumes one).
- **Pricing multipliers**: 5m write **1.25×** input; 1h write **2×** input; cache read **0.1×** input — and **0.025× for Claude Fable 5.1 and Mythos 5.1** (i.e., cache reads on your Claude model are 2.5% of input price, not 10%).
- **Minimum cacheable prefix**: Fable 5.1 / Fable 5 / Opus 5 / Mythos = **512 tokens**; Sonnet 5 / Opus 4.8 / Sonnet 4.6/4.5 = 1,024; **Haiku 4.5 = 4,096**; Opus 4.7 = 2,048; Opus 4.6/4.5 = 4,096. Shorter prompts silently don't cache (no error) — check `usage`.
- **Prefix order** `tools → system → messages`; a change at one level invalidates that level and everything after. Tool-definition changes invalidate everything; `tool_choice`, images added/removed, and (model-specifically) thinking parameters / effort invalidate system+messages.
- **Lookback window 20 blocks** for automatic prefix matching; consecutive `tool_use`/`tool_result` blocks count as one position.
- **Refresh**: "The cache is refreshed for no additional cost each time the cached content is used." Lifetime is measured from the *start* of the request that wrote/read it.
- **Concurrency**: "a cache entry only becomes available after the first response begins. If you need cache hits for parallel requests, wait for the first response before sending subsequent requests." (Critical for parallel subagent fan-out — see §5a.)
- `input_tokens` in usage = **only tokens after the last breakpoint**; total input = `cache_read + cache_creation + input_tokens`.
- Thinking blocks in prior turns are cached as content and *do* count as input when read from cache; on Opus 4.5+/Sonnet 4.6+ they're preserved by default so the cache stays valid.
- ZDR-eligible; caches isolated per org (and per workspace on some providers).

### 2.2 How Claude Code applies caching [DOC] — https://code.claude.com/docs/en/prompt-caching
- Layers ordered for prefix stability: **System prompt** (core instructions, tool defs, output style — changes on tool-set change or upgrade) → **Project context** (CLAUDE.md, auto memory, unscoped rules — changes at session start / `/clear` / `/compact`) → **Conversation** (every turn).
- **Model and effort level are part of the cache key**: "each effort level has its own cache for the same model. Changing effort mid-session recomputes the entire request."
- **Actions that invalidate**: switching models (incl. `opusplan` toggles and automatic safety fallback on Fable 5.1/5/Opus 5), changing effort, turning on fast mode, MCP server connect/disconnect **when tools are loaded into the prefix** (deferred tools — the default via tool search — only append), enabling/disabling plugins that add MCP servers, adding a bare tool-name deny rule, compaction, upgrading Claude Code (resuming an old session after an upgrade "can be the most expensive request you send").
- **Actions that keep the cache**: editing repo files (Claude Code appends a `<system-reminder>` rather than mutating history), **editing CLAUDE.md mid-session** (kept in memory; edit doesn't invalidate but *also doesn't apply* until `/clear`/`/compact`/restart), output style change, permission-mode change, invoking skills/commands (appended as user messages), `/recap`, `/rewind` (truncates back to an already-cached prefix), spawning a subagent.
- **Compaction cost**: the summarization request reuses the warm prefix, so "a mid-session `/compact` costs a fraction of what the context size suggests"; after a break longer than the TTL it reprocesses the full history uncached — "why `/compact` costs the most when you resume an old session." Prefer `/rewind` over `/compact` when abandoning a path.
- **TTL buckets**: *Main conversation* gets **1h on a Claude subscription within plan usage**, **5m on usage credits / API key / cloud provider**. *Everything else* (subagents, workflows, teammates, forks, compaction, session titles) gets **5m** by default.
- **Choose TTL yourself** (v2.1.242+): `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL` (main), `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (everything else); values `5m`|`1h`. Precedence: `FORCE_PROMPT_CACHING_5M=1` → bucket env var → bucket setting → subagent frontmatter `experimental: {cacheTtl: 1h}` (v2.1.248+; ignored while on usage credits) → **`ENABLE_PROMPT_CACHING_1H=1` (requests 1h for both buckets)** → bucket default. Verify with `claude -p "hello" --output-format json` → `usage.cache_creation.ephemeral_1h_input_tokens`.
- **Cache scope**: "effectively scoped to one machine and directory" — system prompt embeds cwd, platform, shell, OS, auto-memory paths; worktrees don't share. "Sequential sessions share the prefix only when the git status snapshot at startup matches." (So the first turn of every new session reprocesses your system prompt + CLAUDE.md unless the git snapshot is identical — see §5g.)
- **Subagents**: own system prompt + tool set; "Its first request doesn't read the parent's cache… and it warms a cache of its own across its turns." Forks inherit the parent's prefix exactly and read its cache. In a **workflow fan-out** of same-prefix agents, "Claude Code briefly holds all but the first so their first requests can read the prefix the first agent cached."
- **Disable**: `DISABLE_PROMPT_CACHING[_HAIKU|_SONNET|_OPUS|_FABLE]=1`.
- **Observability**: `/usage` shows a `Prompt cache (main)` line (v2.1.251+): request count, % input from cache, misses (>5% and ≥2,000 tokens re-processed), expected rebuilds, warm/cold with TTL. Covers main conversation only, not subagents. https://code.claude.com/docs/en/costs
- Design rationale (first-party blog): "we run alerts on our prompt cache hit rate and declare SEVs if they're too low"; hierarchy static system+tools → CLAUDE.md → session context → messages; plan mode implemented as tools (`EnterPlanMode`/`ExitPlanMode`) precisely to avoid a cache break; deferred tool stubs "always present in the same order"; advice: "Use messages for updates rather than system prompt changes. Never change models… mid-conversation. Monitor cache hit rate like uptime metrics." https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything

### 2.3 Context, compaction, `/context`, `/cost` [DOC]
- `/cost` has been folded into `/usage` (Session block shows tokens by model incl. cache read/write and local dollar estimate; resets on `/clear` since v2.1.211). https://code.claude.com/docs/en/costs
- `/context` — live breakdown by category with optimization suggestions, including which CLAUDE.md/memory files loaded. https://code.claude.com/docs/en/context-window
- **What survives compaction**: project-root CLAUDE.md and unscoped rules re-injected from disk; `paths:` rules and nested CLAUDE.md reload as matching files are read; **invoked skill bodies re-injected capped at 5,000 tokens per skill and 25,000 total, oldest dropped first, truncation keeps the start of the file**; `SessionStart` hooks with `compact` matcher run and add output; **skill descriptions are not re-injected**. https://code.claude.com/docs/en/context-window
- Auto-compact window: `/autocompact 500k`, `--autocompact`, or `CLAUDE_CODE_AUTO_COMPACT_WINDOW=<tokens>` (100K–1M). Fable 5.1 runs a 1M window by default on the API; Sonnet 5 auto-compacts ~967K. https://code.claude.com/docs/en/model-config
- Custom compaction guidance: `/compact <instructions>`, or a `# Compact instructions` section in CLAUDE.md; partial compaction via `/rewind` → "Summarize from/up to here"; `/btw` side questions never enter history. https://code.claude.com/docs/en/best-practices
- Size guidance: CLAUDE.md "target under 200 lines… Longer files consume more context and reduce adherence"; **`@path` imports load at launch and do not reduce context** ("Splitting into `@path` imports helps organization but doesn't reduce context"); nested CLAUDE.md and `paths:` rules load lazily; **block-level HTML comments are stripped before injection** (free maintainer notes); auto memory MEMORY.md first 200 lines / 25 KB; CLAUDE.md up to 4 MiB loaded in full. https://code.claude.com/docs/en/memory
- Skills: listing of names+descriptions costs a budget of **1% of the context window** (`skillListingBudgetFraction`, `SLASH_COMMAND_TOOL_CHAR_BUDGET`), each entry capped at 1,536 chars; body loads only on invocation; `disable-model-invocation: true` keeps even the description out of context; subagents with `skills:` frontmatter get the **full skill body injected at startup**; `context: fork` + `agent: Explore` sees only SKILL.md + agent prompt (Explore/Plan skip CLAUDE.md and git status). https://code.claude.com/docs/en/skills
- Costs page tips (all [DOC]): "Offload processing to hooks and skills" (PreToolUse `updatedInput` rewriting `npm test` to `| grep -A 5 FAIL | head -100`); "Move instructions from CLAUDE.md to skills… Aim to keep CLAUDE.md under 200 lines"; prefer CLI tools over MCP; "Delegate verbose operations to subagents"; agent teams ≈7× tokens; extended thinking billed as output and can't be disabled on Fable — use `/effort`. https://code.claude.com/docs/en/costs

### 2.4 Subagent isolation & model choice [DOC] — https://code.claude.com/docs/en/sub-agents
- "Each subagent starts with a fresh, isolated context window." Initial context: its own system prompt (agent body), task message, **full CLAUDE.md hierarchy**, git status snapshot, preloaded skills, sibling roster. Not inherited: parent history, invoked skills, parent auto memory, output style.
- Model: `sonnet|opus|haiku|fable|inherit` or full ID; resolution = per-invocation → frontmatter `model` → `CLAUDE_CODE_SUBAGENT_MODEL` → main model. "Control costs by routing tasks to faster, cheaper models like Haiku."
- `experimental: {cacheTtl: 1h}` frontmatter (v2.1.248+). `maxTurns` returns partial output. 20 concurrent subagent limit by default. Background subagents get a reduced tool set.
- "the verbose output stays in the subagent's context while only the relevant summary returns to your main conversation."
- Context-window page: "The subagent loads CLAUDE.md too. Same file, same content, but it counts against the subagent's context, not yours. The built-in Explore and Plan agents skip this for a smaller context." https://code.claude.com/docs/en/context-window

### 2.5 Effort [DOC] — https://code.claude.com/docs/en/model-config
- Fable 5.1 levels: `low|medium|high|xhigh|max`; default `high`. `/effort`, `--effort`, `CLAUDE_CODE_EFFORT_LEVEL`, `effortLevel`/`modelSettings`. `medium` "Reduces token usage for cost-sensitive work that can trade off some intelligence"; `max` "prone to overthinking. Test before adopting broadly." "The effort scale is calibrated per model." Thinking cannot be turned off on Fable 5.1. Changing effort mid-session breaks the cache (§2.2).

### 2.6 API-level context editing [DOC] — https://platform.claude.com/docs/en/build-with-claude/context-editing
- `clear_tool_uses_20250919`: trigger default 100k input tokens, `keep` 3, `clear_at_least`, `exclude_tools`. **"Invalidates cached prompt prefixes when content is cleared… Use the `clear_at_least` parameter"** so the invalidation is worth it. Claude Code exposes this indirectly as "tool-result clearing" (counted as an "expected rebuild" in `/usage`).

### 2.7 Agent SDK cross-machine caching [DOC] — https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts
- `excludeDynamicSections: true` (SDK) / `--exclude-dynamic-system-prompt-sections` (CLI `-p`) moves cwd/git/platform/OS/memory-path context into the first user message so identical configurations share a system-prompt cache across machines and directories. Tradeoff: "Instructions in the user message carry marginally less weight." TypeScript SDK also has `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` to split a custom system prompt into static/dynamic blocks with separate breakpoints.

### 2.8 Anthropic engineering guidance [DOC, first-party]
- *Effective context engineering*: "Context… must be treated as a finite resource with diminishing marginal returns"; "striving for the minimal set of information that fully outlines your expected behavior"; hybrid retrieval (CLAUDE.md upfront + glob/grep just-in-time); compaction should preserve "architectural decisions, unresolved bugs, and implementation details while discarding redundant tool outputs"; **tool-result clearing is the low-risk starting point**; structured note-taking (NOTES.md); sub-agents return "a condensed, distilled summary… (often 1,000-2,000 tokens)". https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- *Building effective agents*: routing "easy/common questions to smaller, cost-efficient models like Claude Haiku 4.5 and hard/unusual questions to more capable models"; prompt chaining trades latency for accuracy; orchestrator-workers. https://www.anthropic.com/engineering/building-effective-agents
- *Agent Skills*: three-level progressive disclosure (metadata → SKILL.md → bundled files); "the amount of context that can be bundled into a skill is effectively unbounded"; **"sorting a list via token generation is far more expensive than simply running a sorting algorithm. Beyond efficiency concerns, many applications require the deterministic reliability that only code can provide."** https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills
- *Best practices*: "Most best practices are based on one constraint: Claude's context window fills up fast, and performance degrades as it fills"; "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"; "After two failed corrections, `/clear`"; adversarial review in a fresh subagent; "A reviewer prompted to find gaps will usually report some, even when the work is sound." https://code.claude.com/docs/en/best-practices

**→ us (Claude Code side)**
- *Applies now, zero quality risk*: set `CLAUDE_CODE_PROMPT_CACHE_TTL=1h` if you ever run on API key/usage credits; never change model/effort mid-session; don't toggle MCP servers/plugins mid-session; pick effort at session start; run `/usage` and watch the `Prompt cache (main)` line; use `/rewind` instead of `/compact` to abandon paths.
- *Applies with a test*: whether N parallel subagents with identical agent definition + CLAUDE.md actually share a cache (docs only guarantee the "hold all but the first" behavior for *workflow* fan-out; API says entry available once first response begins). Measure `cache_read_input_tokens` on subagent 2..N.
- *Does not apply*: Osmani-style web caching; Agent SDK `excludeDynamicSections` unless you drive runs through `claude -p`/SDK — but if you do, it's a real cross-session win.

- **Implicit caching**: "enabled by default for all Gemini 2.5 and newer models… We automatically pass on cost savings if your request hits caches." ## 4. Community / industry patterns

- **Hermes Agent (Nous Research)** [COMMUNITY, first-party docs of an OSS project]: two compression layers (gateway at 85% of context; agent `ContextCompressor` at 50% configurable); **Phase 1 is tool-result pruning with no LLM call** (results >200 chars replaced by "[Old tool output cleared to save context space]"); protects system + first exchange and the last 20 messages; structured summary with mandatory sections (Goal, Constraints, Progress Done/In-Progress/Blocked, Key Decisions, Relevant Files, Next Steps); "lean" tail = 2.5% of window with regex-extracted anchors (SHAs, paths, error strings) and **every real user message verbatim**. Anthropic caching strategy "system_and_3": breakpoint 1 on system prompt, 2–4 rolling over the last three messages; default `5m`, optional `1h`. ## 5. Evaluation of your specific ideas

### (a) Stable material (METHOD.md, templates, glossary) at the very front → cacheable prefix
- **Evidence for**: Anthropic prefix rule and Claude Code layer table (§2.1–2.2); Gemini "large and common contents at the beginning" (§3.1); Codex, Hermes, OpenClaw all order stable → volatile.
- **Mechanics in Claude Code**: you don't order raw requests, but placement decides the layer. In the **main session**, content in CLAUDE.md (or `@import`ed) lands in the Project-context layer — already the most stable position after the system prompt. In **subagents**, the agent `.md` body *is* the system prompt and CLAUDE.md is loaded too, so stable instructions belong in the **agent definition or CLAUDE.md, not in each dispatch message**. Anything task-specific goes last in the dispatch message. For fan-out, all N subagents then share an identical prefix up to the task line; the API only exposes the entry after the first response begins (§2.1) — Claude Code stagger-holds only *workflow* fan-outs. **Test**: dispatch 5 identical-definition subagents; compare `cache_read_input_tokens` on #2–5 (via OTel/`--output-format json` or the subagent transcripts).
- **Economics on Fable 5.1**: cache reads are 0.025× input, so a 10k-token METHOD.md costs ~250 tokens-equivalent per turn once cached vs 10k uncached; the first turn per subagent pays a 1.25× (5m) write. That means **the prefix cost is not your problem once caching works — re-processing on cache misses and the *attention* cost are.**
- **Antigravity**: same ordering rule; 4,096-token minimum is met. Benefit contingent on §3.2 test.
- **Quality risk**: none from ordering. Minor risk if you move guidance from CLAUDE.md (system-adjacent) to a user-message position — docs note user-message instructions "carry marginally less weight" (§2.7).

### (b) Pre-compute deterministic extraction with scripts
- **Evidence for** [DOC]: Anthropic Skills post ("sorting a list via token generation is far more expensive than simply running a sorting algorithm… deterministic reliability that only code can provide"); costs page hook example (grep test output before Claude sees it); Fowler's computational-vs-inferential distinction; Osmani's hooks as the substitution mechanism (exit 2 / `updatedInput`).
- **How**: a `SessionStart` hook (matcher `startup|resume|compact`) that runs your inventory script and injects `additionalContext` (file list, sizes, hashes, last test exit codes, STATE.md digest) — deterministic, cheap, and re-injected after compaction. A `PreToolUse` hook on `Bash` can rewrite verbose commands to filtered forms.
- **Quality risk**: low for facts that are truly mechanical (sizes, paths, hashes, exit codes). Medium if scripts *summarize* content — then the model reasons over a lossy view. Mitigation: scripts emit **paths to full artifacts** so the model can drill in JIT (Anthropic's hybrid retrieval pattern).

### (c) Content-hash dedupe so byte-identical sources are read once
- **Evidence**: no harness does this natively. Two distinct things get conflated:
  1. *Within one context*, a second `Read` of the same file is wasteful — but the content must be in context for the model to use it; after compaction it may be gone (only "files modified most recently" are re-read). A `PreToolUse` hook that blocks re-reads of unchanged files with "already in context" is possible but **dangerous after compaction** — you'd have to track compaction (via `PreCompact`/`SessionStart compact`) and reset the seen-set. Needs a test; modest savings.
  2. *Across subagents/sessions*, the real win is **memoizing deliverables**: key = `sha256(sorted input file hashes) + sha256(METHOD.md) + sha256(prompt template) + model + effort`; if a prior deliverable exists with that key, skip dispatch and reuse (Osmani's stored-result pattern, keyed properly). This is where "each is read once" pays off — one subagent read per unique input set, not per session.
- **Quality risk**: staleness if the key omits an input that matters (METHOD/glossary version, model, effort). Keep the key strict and surface the key in the deliverable header so auditors can see what it was derived from. Deterministic and auditable — arguably *raises* rigor.

### (d) Model tiering — Flash/Haiku for mechanical extraction, Pro/Fable for judgment — **WITHDRAWN (quality trade; kept as research only)**
- **Evidence for** [DOC]: Anthropic "Building effective agents" routing; Claude Code docs "For simple subagent tasks, specify `model: haiku`"; Haiku 4.5 = "similar levels of coding performance" to Sonnet 4 at one-third cost, SWE-bench Verified 73.3%, positioned for "sub-agent orchestration" https://www.anthropic.com/news/claude-haiku-4-5 ; Antigravity `model: flash` per subagent and the 8× quota example.
- **Evidence on verbatim-extraction quality specifically: none found in first-party docs; third-party "hallucination rate" pages are SEO-grade and I would not cite them [?].** What exists is indirect: Chroma shows even frontier models fail at *literal replication* ("repeated words") as context grows — so extraction faithfulness is a context-length problem for *every* tier, not just small models.
- **Gotchas**: Haiku 4.5's minimum cacheable prefix is **4,096 tokens** (vs 512 on Fable 5.1) — small extraction prompts may not cache at all; a Haiku subagent is a separate model, so nothing it does is shared with the Fable cache. Antigravity Flash: 3.1 Pro/3.x Flash both need 4,096.
- **Make the risk checkable instead of arguing about it**: have any extraction subagent emit quotes in a form a script can verify byte-for-byte against source (`grep -F` / exact substring with path:line). That converts tier choice from a quality gamble into a measured error rate; run the same extraction task on Flash/Haiku vs Pro/Fable on a sample and compare verified-quote rates before switching. (Anthropic's Citations API does verified `cited_text` with char offsets and doesn't count toward output tokens — but it's a raw-API feature, not something Claude Code's Read tool gives you. https://platform.claude.com/docs/en/build-with-claude/citations )
- **Quality risk**: medium and *task-dependent*; low for "list every occurrence of X with line numbers", higher for "extract the relevant clauses" (judgment hidden inside extraction). Also: lowering *effort* instead of model is a cheaper first step on Fable — but it's a session-wide cache-key change, so set it per subagent definition, not mid-session.

### (e) Short report messages + deliverables on disk (already done)
- **Evidence** [DOC + COMMUNITY]: Anthropic "1,000-2,000 tokens" condensed summaries; Claude Code "only the relevant summary returns"; HumanLayer file-referenced findings; Antigravity Teamwork artifacts. Consensus; keep it. Refinements: fixed report schema (what changed / where / open questions / verification evidence) and **file:line references** so the parent can drill in JIT rather than re-read wholesale.
- **Quality risk**: only if the summary drops verification evidence; require the report to cite the checks it ran.

### (f) Smaller METHOD.md / per-phase files loaded just-in-time
- **Evidence for** [DOC]: CLAUDE.md "<200 lines… reduce adherence"; "Bloated CLAUDE.md files cause Claude to ignore your actual instructions"; skills load on demand; `paths:` rules; Codex 32 KiB AGENTS.md cap and "reference task-specific markdown files"; Chroma distractor findings.
- **Evidence tempering the *cost* argument**: once cached, a 40 KB prefix costs 2.5% (Fable 5.1) or 10% per turn — cheap. **The strong argument for splitting is adherence/attention, not tokens.** But `@import` does *not* save context; only skills, `paths:` rules, nested CLAUDE.md, or explicit reads do.
- **Compaction trap**: skill bodies re-inject after `/compact` **capped at 5,000 tokens per skill, 25,000 total, keeping the start of the file** — a 10k-token phase file will be silently truncated after compaction. Put non-negotiables at the top of each phase file, and/or re-inject the current phase via a `SessionStart compact` hook, and/or preload the phase skill into subagent definitions (`skills:` frontmatter → full body at startup, deterministic).
- **Quality risk**: medium if you rely on the model to *choose* to load the right phase file; low if loading is deterministic (skill preload, `/phase-N` invocation, hook injection). Keep a short always-on core (invariants, glossary pointers, "where the phase files are") and make phase loading mechanical.

### (g) Session length vs cache TTL alignment
- **Facts**: cache refreshes on every hit at no extra cost, so continuous work never expires — the risk is **gaps longer than the TTL** (human breaks, long script runs, waiting on subagents). Claude subscription within plan: main conversation 1h, subagents 5m; API key / usage credits: 5m for everything unless `CLAUDE_CODE_PROMPT_CACHE_TTL=1h` (or `ENABLE_PROMPT_CACHING_1H=1` for both buckets). 1h writes cost 2× vs 1.25× — pays only if gaps between 5 and 60 minutes actually occur (§2.2 explicitly: it "costs more on short bursts of work that never idle past five minutes").
- **Subagents**: a subagent that runs continuously and finishes never idles >5m → `1h` for them is pure cost; leave at 5m unless a subagent waits on long builds. Set per definition via `experimental: {cacheTtl: 1h}` only for those.
- **Session boundaries**: each new session reprocesses system prompt + CLAUDE.md unless the git snapshot matches; resuming after a Claude Code upgrade reprocesses the entire history. So *fewer, longer sessions with disciplined compaction* are cheaper than many short ones — but only if the per-turn history stays small enough for quality (HumanLayer's 40–60% heuristic [COMMUNITY]).
- **Gemini/Antigravity**: implicit cache lifetime undocumented [?]; explicit 1h default with $4.50/M/hr storage (10k tokens ≈ $0.045/hr — trivial, but not exposed by agy).
- **Quality risk**: none from TTL; the quality risk lives in the compaction you'd do to keep long sessions viable — mitigate with `/compact <instructions>` and a `# Compact instructions` block that pins STATE/decisions.
