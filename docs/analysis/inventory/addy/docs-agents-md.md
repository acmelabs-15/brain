# docs/agents.md

## Purpose — required, verbatim
> "Specialist personas that play a single role with a single perspective. Each persona is a Markdown file consumed as a system prompt by your harness (Claude Code, Cursor, Copilot, etc.)." — docs/agents.md:3

## Design intent — required
Establishes the architectural taxonomy, role boundaries, and orchestration patterns for agent personas within the `agent-skills` repository. Formulates a foundational three-layer model (`Skill` / `Persona` / `Command`) that cleanly disentangles *how* (procedural workflows with exit criteria), *who* (system-prompt viewpoints enforcing strict report schemas), and *when* (composition entry points). Enforces strict anti-pattern prohibitions against peer-to-peer persona delegation ("Personas do not call other personas") and meta-orchestrators ("decide which other persona to call") to eliminate multi-hop paraphrasing degradation and recursive routing loops. Defines `/ship` as the single canonical fan-out orchestrator for parallel independent assessments (`code-reviewer`, `security-auditor`, `test-engineer`), provides a decision matrix for direct invocation vs. slash commands vs. sequential pipelines, and details concrete platform interop rules for Claude Code subagents and experimental Agent Teams.

## Observations
- Three-Layer Separation of Concerns: Clearly formalizes the conceptual hierarchy: `Skill` (*how* — procedural workflow), `Persona` (*who* — role viewpoint and output format), and `Command` (*when* — user entry point composing personas and skills).
- Anti-Pattern Guard Rails: Explicitly outlaws peer-to-peer persona delegation ("Personas do not call other personas") and meta-orchestrator personas, directly preventing token bloat, information loss from paraphrasing hops, and infinite routing loops.
- Platform Alignment: Accurately reflects Claude Code platform constraints (*"subagents cannot spawn other subagents"*), converting an external platform boundary into an architectural discipline.
- Platform Capability Degradation Guard: Notes that plugin agents do not support `hooks`, `mcpServers`, or `permissionMode` frontmatter, ensuring agent persona authors do not configure inert frontmatter keys.
