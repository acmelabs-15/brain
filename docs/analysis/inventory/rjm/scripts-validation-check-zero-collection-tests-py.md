# scripts/validation/check_zero_collection_tests.py

## Purpose — required, verbatim
> "Fail when a file pytest walks into contributes no tests." — scripts/validation/check_zero_collection_tests.py:6

## Design intent — required
Ensures that any test file walked by pytest (matching `python_files` under `testpaths` in `pyproject.toml`) contributes at least one test case rather than silently collecting zero tests. When a test file contains no tests, pytest passes without error or notice, leaving dead test code or broken harnesses unmonitored (as uncovered in issue #4494). The script acts as a strict verification gate during CI and pre-push runs. It supports two explicit exemption declarations in source comments or docstrings: permanent exemptions (`pytest-zero-collection: <reason>`) for non-test helper files (which fail if they ever start collecting tests, preventing stale exemptions), and conditional skips (`pytest-zero-collection-conditional: <reason>`) for tests skipped during collection on certain environments.
