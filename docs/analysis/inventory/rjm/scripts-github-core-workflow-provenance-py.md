## Purpose — required, verbatim
> "Resolve each run's workflow definition from the ref GitHub will evaluate." — scripts/github_core/workflow_provenance.py:1

## Design intent — required
Bulk run cancellation safety requires verifying that every cancelled required status check can be regenerated by checking the workflow's trigger events. However, reading workflow YAML from a local checkout only reflects the current local commit rather than the ref GitHub evaluates. For pull request triggers, GitHub evaluates the workflow file at the pull request merge ref (`refs/pull/<n>/merge`), meaning PR branches can modify event subscriptions (such as omitting `reopened`). This module fetches workflow documents directly from GitHub's REST contents API at the pull request merge ref and merges them with base branch subscriptions using `pin_to_head_ref`. Any resolution failure (e.g. merge conflict or deleted workflow file) blocks the run fail-closed.
