# scripts/validation/validate_hook_anchoring.py

## Purpose — required, verbatim
> "Gate: every plugin hook artifact anchors its scripts to the plugin root." — scripts/validation/validate_hook_anchoring.py:2

## Design intent — required
Enforces that every plugin hook command across Claude Code and GitHub Copilot CLI platforms is explicitly anchored to the plugin's installation root directory rather than executed with a bare relative path. When Claude Code or Copilot CLI executes a hook script, the process working directory (`cwd`) is set to the end-user's project workspace, not the plugin's install location. Consequently, unanchored paths such as `./hooks/...` fail with "No such file or directory" in customer environments (incident #2205). This gate validates that Claude hooks (`.claude/hooks/hooks.json`) anchor commands using `${CLAUDE_PLUGIN_ROOT}`, and that generated Copilot hooks (`src/copilot-cli/hooks/hooks.json` and any platform defined in `templates/platforms/*.yaml`) strictly conform to the command shapes generated by `build/scripts/generate_hooks.py` and `build/scripts/generate_dispatcher.py` (which use `${COPILOT_PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}` and PowerShell counterparts). The gate explicitly handles ADR-097 (retired tool hooks leaving empty `"hooks": {}`), verifying that empty manifests report zero entries rather than passing silently, while maintaining fail-closed behavior for missing or unparseable manifests.
