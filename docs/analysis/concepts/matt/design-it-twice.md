A module candidate identified for deepening with its constraints and dependencies

## Produces
Three or more radically different candidate interface designs generated by parallel subagents

## When applied
When designing or refactoring a critical module interface to explore multiple trade-offs before settling on an API

## Design notes
Inspired by John Ousterhout's principle, Design It Twice counters the cognitive bias of committing to the first workable interface design by spawning multiple subagents with conflicting constraints (minimal interface, maximal flexibility, default simplicity) to evaluate competing architectures.
